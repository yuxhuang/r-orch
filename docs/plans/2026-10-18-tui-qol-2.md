## Goal

Make entity lists easy to filter and sort, and details consistent to navigate and read. Deliver the approved R1–R13 plus
review clarifications R14/R16 and lead-ruled R15 in two independently rooted PR stacks, preserving existing domain data and terminal
interactions.

- Persisted sort/filter settings or new timestamp fields: session state and derived values suffice.
- Regex/fuzzy search or a general table framework: substring matching and existing row/hit-map machinery suffice.
- Changing `/`, clipboard/editor behavior, Logs filtering, engine scheduling or peer contracts: outside the approved scope.
- A release, merge, browser redesign or native terminal acceptance: only stacked PR creation is authorized here.

## Assumptions and invariants

Verified at base: Goal has created_at/optional updated_at; Task has no durable start; runs/running entries have starts.
Message has agent/task ids but no goal id; goal matching must join structured task ids, never scrape text.
Task/goal metadata edits also change terminal updated_at (`orch-engine` task_service.rs:409, goal_service.rs:198).
Run start is recorded while Preparing (run_service.rs:65–85), not necessarily process launch. R15 disclosure is lead-ruled 2026-10-18, pending owner notice.
Unverified workload: one operator, hundreds of rows, bounded activity; archive size/latency remain unmeasured.
Must preserve identity, safe text, unknown values and stable sorts. No comparator/render I/O. Timing is wall span
including waits/retries/paused time, not execution accounting; bounded activity/live tasks do not bound retained runs.

## Design

1. **D1 — per-list keyword state.** In `state.rs`, each entity list gets `keyword: String` in its list-controls
   state, plus an explicit keyword-prompt mode using the existing `TextInput`. Ctrl+K opens it only from an
   entity main list; `/` remains command mode. Typing/paste applies live; Enter keeps the value and exits; Esc
   clears and exits. Ctrl+U outside the prompt and a sort-bar keyword chip clear it. Bound every input path to
   256 Unicode scalar values and strip control characters before insertion; use safe display for the chip.
   Match a case-insensitive substring against each full, untruncated metadata field independently: id,
   title/name, canonical and displayed status, assignee id/resolved name, active team id/name, and displayed
   adapter/model/node or goal label where applicable. Do not match hidden descriptions or dynamic time text.
   Empty matches all. Predicate goes inside each `sorted_*` **before sort, grouping and show-all truncation**;
   empty groups disappear and counts describe matches. Capture selected id from the committed actionable
   order BEFORE changing entities, controls or comparator time. Reconcile on refresh or sort/filter/group/show-all
   change: sample sort-time, derive final visible order, re-find the id (else clamp to nearest position), commit together.
   Between reconciliations, ticks advance displayed elapsed only; rendering/navigation/actions use committed order.
   Never derive an action target or the old id using a fresh clock. Clock-only ticks cannot push selection out of
   the task cap. Explicit reconciliation may: clamp without auto-show-all or pinning, and defer entity actions
   until the new order/selection is drawn. Empty results have no entity target; pseudo rows cannot become entities.
   Help: "Elapsed order updates on refresh or list-control changes; displayed time is live."
   Rejected: render-only filtering breaks navigation; global keyword couples lists; `/` conflicts with approval.
   Continuous re-sorting with per-frame reconciliation is viable but adds row motion/cap churn; sampled order
   trades one refresh interval of rank freshness for stable interaction, with no new storage contract.
2. **D2 — typed sort plus headers.** Generalize `AgentSort` into `ListSort<F> { field, direction }` with typed
   Goal/Task/Agent field enums and Asc/Desc direction; retain old agent behavior through aliases/wrappers if
   needed by callers/tests. Goals: Status, Title, Progress, Assignee, Started, Elapsed; Tasks: Status, Priority,
   Title, Assignee, Goal, Started, Elapsed; Agents retain Original, Name, Status, AdapterModel, Location.
   Defaults are status ascending/source ties for goals/tasks and Original ascending for agents. `o` cycles,
   retaining the current direction; `O` flips, `0` resets only that list's sort. Clicking an inactive header
   selects that field ascending; clicking the active header flips its direction. These are distinct transitions.
   Original is a sort-bar reset mode, marked there rather than pretending it is a sortable data column. Reuse agents' existing name/id tie rules and Original source-order semantics; goal/task equal keys
   keep source order in both directions. Agent Original descending explicitly reverses its status/source
   comparator within each fixed group (including source-order ties), retaining the existing regression;
   the no-reversed-ties rule applies to goal/task equal keys, not that legacy mode. Unknown values stay last
   in either direction. Progress compares the
   done/total ratio (no tasks = unknown), dates/durations compare numeric milliseconds, text compares normalized
   text. Header widths come from the same column geometry as rows; active marker is `↑/↓`. Use a typed
   `ZoneKind::SortHeader { view, field }` and matching `ZoneId`; group/filter controls use `Verb` zones. Keep
   clipping, generation checks and press/release identity. Task grouping remains sort-then-first-appearance
   regroup, ungrouped last; agent group order is independent of sort direction. Header/chrome rows are not
   selectable and reduce viewport height before scroll math. Rejected: global sorting across groups destroys
   sections; reversing the final vector reverses groups/ties and puts unknowns first.
3. **D3 — derived timing sidecar.** Keep domain Task/Goal unchanged. Add a TUI `EntityTiming` with
   `started_at_ms: Option<i64>` and `elapsed_ms: Option<i64>` (UTC epoch ms and nonnegative duration ms), held
   in id-keyed task/goal maps. CLI `tui/backend.rs` derives them from all retained run records and the same
   refresh's task/goal/orchestrator snapshot: task start = minimum valid run `started_at`, also considering
   `orch_state.running[task].started_at` (covers a live first run not yet in history); goal start = parsed
   `created_at`. No run means both task fields None; malformed/missing timestamps stay unknown. Terminal
   means Done/Failed/Cancelled or Achieved/Abandoned; endpoint is `updated_at`, with absent/invalid endpoint
   yielding None elapsed, not fabricated zero. Other started entities use now; clamp negative deltas to zero.
   Terminal values freeze against now, not metadata edits; the formula does not establish completion duration.
   **RT2 Option A, lead-ruled 2026-10-18, pending owner notice (`tsk_zlHpODr`):** retain R11 and the approved
   formula/interface; Goals and Tasks use the `Elapsed*` column header. The help overlay and README table/sort
   section carry this exact sentence:
   "Elapsed*: start to now; terminal rows end at last update (edits change it). Includes waiting/retries."
   README also states that task Started = earliest retained run record (including Preparing), not process launch;
   goal Started remains creation time. A persistent list hint is optional; header asterisk + help overlay line +
   README is the minimum. Sort on the displayed span, never a separate completion duration, with D1's sampling
   policy. Unknown terminal duration (B) and durable completion timestamps (C) are owner-decidable follow-ups,
   not adopted in this goal. Y2 may proceed under this ruling; the vectors below are mandatory.
   Additive facade method approved by lead ruling `tsk__z-Crg7`: `fn refresh_timings(&mut self, tasks: &[Task], goals: &[Goal],
   orch_state: Option<&OrchestratorState>, now_ms: i64) -> BackendResult<TimingSnapshot>`. Snapshot fields are
   `tasks` and `goals` (`HashMap<String, EntityTiming>`) plus `sampled_at_ms: i64`; the default returns empty
   maps stamped with now. Existing refresh signatures stay unchanged. Wire once after refreshing entities
   and state; pass None when current orchestrator state is unavailable, not an old successful snapshot. Backend aggregates runs once per refresh, never per row and never from the
   ten-run history sample; failure yields a visible error and unknown task history, not "never started" as a
   factual assertion. UI advances displayed nonterminal elapsed from start with the injected frame clock.
   Comparator elapsed
   uses D1's last reconciliation time; display and sort use the same time only at reconciliation. This replaces
   v1's every-frame sort/render-clock rule and prevents clock-only action retargeting. Started uses
   `relative_time(start, now)` and Elapsed `format_duration(ms)`; None is blank. Rejected: persisted fields require migration; task created time or latest retry start is not the
   approved start; run `finished_at` is not the approved terminal endpoint.
4. **D4 — grouping is independent state.** `AgentGroupBy = Team | Node`, Team by default; `b` and a clickable
   By team/By node chip toggle it in the Agents main list. Generalize the group key used by both `sorted_agents`
   and `agent_rows`, leaving `team_of` available for membership/display. Node keys are Local then remote aliases
   in deterministic lexical order; group identity uses the exact alias, never a lossy lowercased collision.
   Nonempty groups only; mark remote online/offline from the supplied flags (mixed flags conservatively offline).
   A retained offline agent stays visible. Preserve selection by id and sort within groups. Rejected: a second
   remote-only list duplicates state; inferring node from display names is ambiguous.
5. **D5 — shared Activity row and stable rail.** Extract a pure row builder from `views/activity.rs:146–219`,
   taking message, resolved agent display/color, width, now, selected state and previous-agent/group context;
   return spans. Feed and detail callers own their zones/anchors, preventing a detail click from targeting the
   feed selection. Keep rich grouping/error styles and safe truncation. Goal/Agent details are newest-first
   (descending timestamp, then message id); existing feed/Task chronology remains unchanged. Append
   GoalSection::Activity and AgentSection::Activity last in `focus_ring`, including their empty states. Agent membership is exact `agent_id`; goal membership joins `task_id` against **all** tasks of
   that goal, independent of the main-list filter; include explicit goal-id records if the feed gains them.
   At this base there are none; no string search or new persisted event format. Generalize `follow.rs`'s Task
   Activity machinery with pane-scoped message-id anchors and eviction clamp. Following means the newest
   edge: bottom for the existing Task/feed, top for descending Goal/Agent. Home resumes following for
   newest-first Goal/Agent Activity and Down pauses; Task Activity keeps End to resume and Up to pause.
   Browsing away pauses following, and reaching the live edge follows the existing resume policy with orientation mapped.
   Do not reuse bottom-index arithmetic unchanged for descending sections.
   X1 renders rail labels in ring order and styles focus without reordering, including narrow-width clipping.
   Rejected: three copied row builders drift again; sharing the feed cursor couples independent panes.
6. **D6 — Overview block.** In `views/detail.rs`, replace flat text with aligned label/value rows using existing
   Amber labels, status-value tokens and `━` rules; keep every field and the existing two-row pinned summary
   and minimum-height rules. Use display-width clipping and existing tokens, not fixed literal colors.
   Rejected: borders/new widget library conflict with the established chrome and add no information.
7. **D7 — reuse the picker engine.** Single-agent steps use Text + `get_suggestions`/Value mode, following the
   model step. Add agent-only hint matching and Ctrl+O order cycling (Original → Name → Adapter → Status),
   keeping any sentinel first and unfiltered. Empty query shows all eligible agents. Digits 1–9 retain their
   visible numbered-choice shortcut; pasted digits are filter text, and other names can be reached by letters
   or paste. Stable order preserves ties; selection follows the chosen id. Validate the selected choice against
   current eligible ids on submit; arbitrary typed text or removed agents show an error and keep the step open.
   Team members keep Multiselect semantics and selected ids while using the same filter/order controls; do not
   silently convert a member set to a single agent. Rejected: changing every Text step breaks model entry;
   fuzzy name-to-id guessing can assign work to the wrong agent.

Balanced stance (0.5): reuse the current view/input seams and a small typed controls model; reject a table framework
rewrite. Built-in stable [`slice::sort_by`](https://doc.rust-lang.org/std/primitive.slice.html#method.sort_by) provides
the sort primitive; application comparators must define a total order. No new dependency is needed.

```text
key/paste -> prompt validation -> per-list keyword
refresh/control change -> capture id from prior order + sample sort-time + metadata/timings
                                  |
source indices -> keyword predicate -> stable sort -> grouping -> show-all limit
                                  -> restore selected id -> viewport rows + zones
header click / o O 0 -> explicit sort transitions --------^
clock-only tick -> live duration text; committed actionable order unchanged
new order not drawn -> defer entity action -> draw -> actions use displayed order

retained messages -> entity predicate -> newest-first ids -> pane follow/scroll
                                                     -> shared Activity row -> pane-owned zones
```

Builders cover failure/empty/error branches; a silent untested and unhandled failure is a critical gap. QA uses the
spec's tmux scenarios, fake agents, disposable projects, isolated sockets and bounded cleanup; state/render tests alone
cannot pass an on-screen R-row. Add inline pipeline/follow diagrams at changed seams. Pre-PR: `cargo fmt --all --check
&& cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && cargo xtask crate-graph`; `cargo
deny check` if installed. Run on macOS and Linux CI as configured. No cold gate for docs-only S0; security-relevant
implementation follows AGENTS.md. Review typed/pasted text and terminal display; no new shell execution. Never bypass a
failing baseline check.

Performance: keyword adds one metadata scan; stable sorting remains O(n log n) excluding key extraction. Avoid repeated
lowercase allocations inside comparisons and per-row run reads. Existing task regrouping can be quadratic; preserve
behavior first and measure before introducing an index. Correction: `FileRunStore::list_all`
(`orch-infra/src/storage/run.rs:46–71`) reads every retained run JSON and sorts: O(R) file reads and worst-case O(R log
R) ordering, then O(R) min-reduction. The synchronous TUI facade waits for this path; hundreds of tasks do not bound
archive cost. The lead should route a performance-owner measurement of refresh latency for a representative retained
archive and agree a budget before introducing caching/background work. No latency regression is asserted without
measurement. Never put archive reads on the per-frame path.

## Rollback / compatibility

and disappears on restart. Revert a faulty top PR first, then its dependents/ancestors in reverse order as necessary;
never revert a prerequisite while keeping code that uses its interface. Retain the old agent ordering tests and facade
signatures; any landed contract change must go through the lead.
