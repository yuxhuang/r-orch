# TUI quality of life: focus, full text, copy, and safe editing

status: proposed
owner: architect
date: 2026-10-16
revision: v1 — recommendation for domain challenge, not implementation approval
base: `6f54911` on `feature/tui-qol` (fresh fetch of `origin/master`, unchanged at design time)

## Goal

An operator can reach every list and detail section with keyboard or mouse, read a complete retained message or description, copy all or selected text, and leave an editor without silently losing changes. Preserve the existing terminal dashboard and its narrow backend facade. The user's selected draft policy is memory only. This document specifies future behavior; the features have not been implemented or exercised.

Must: no stale-target activation, no silent draft loss, no terminal escape injection from display text, no automatic clipboard write, bounded retained memory, no raw agent text in OSC framing. Should: preserve inspection position during arrivals, immediate visible focus, and responsive scrolling. Performance targets below are acceptance targets, not measured results.

## Scope challenge and alternatives

Three approaches were considered:

- **A — enrich existing panels only:** smallest diff, but duplicates scroll/selection/copy logic across four detail renderers and cannot offer one consistent full-text surface; rejected.
- **B — explicit focus + common read-only viewer + existing editor (recommended):** reuses layout, hit map, backend, Unicode and textarea libraries; changes only the interaction surfaces that lose information.
- **C — new pane framework and replacement editor throughout:** cleaner theoretical uniformity, but introduces unrelated UI migration and dependency risk; rejected for the actual workload.

More than eight files are necessarily affected because input, rendering, backend I/O and editor transitions already live in separate modules. Reduce scope by retaining those modules, adding one viewer widget and one small pure navigation helper, and deferring optional Vim. Do not add a focus framework, async UI framework, search subsystem or new persistence format. Browser clipboard glue is a concrete integration requirement, sent to the lead for scope adjudication (D5/D9).

## Design

### D1. Explicit focus, separate from entity selection

Add `Focus` in `state.rs` with these variants (nested section enums keep the boundary exhaustive):

- `MainList`, `Activity`, `GoalDetail(GoalSection)`, `TaskDetail(TaskSection)`, `AgentDetail(AgentSection)`, `LogDetail(LogSection)`, `TextViewer`.
- `GoalSection = Overview | Description | Progress | Tasks`.
- `TaskSection = Overview | Attachments | Description | Result | Files | Activity`.
- `AgentSection = Overview | Error | Role` (role is the agent's description; overview includes stats, current task, model/command and team information).
- `LogSection = Metadata | Body`.

Every existing detail datum belongs to one section. Empty Description/Role sections remain reachable with an explicit empty state. Optional absent Progress, Error, Attachments, Result, Files and Tasks sections are omitted from the ring; an existing but empty table still renders its empty state. A missing entity closes its detail and restores main focus.

Normal screen ring: `MainList -> Activity -> MainList`; Actions has only `MainList` until its inspector is open; B0 explicitly allocates a lower inspector region in that state (the current Logs layout otherwise reserves no feed height). With details open, replace Activity by the entity's sections in the order above. `Tab` cycles forward, `Shift-Tab`/BackTab backward and wraps. `Left/Right` retain top-level view switching when no detail is open; G/T/A/L retain existing conflicts and capability rules. Document that Tab now moves pane focus, replacing its former top-level-tab behavior. Input/wizard/picker Tab keeps its current meaning.

Render detail sections through a compact section-name rail plus **one section body at a time** in the existing lower rectangle. This is deliberate: at 40x14 there is no useful room for six independently scrollable stacked panes. Tab can reach every available section even when its label is elided; active title is always visible. Mouse on a section label selects that section. Clicking or wheeling in its body focuses it. A maximized detail excludes the zero-height MainList from the ring. Empty ring / too-small screen yields a safe MainList fallback without attempting navigation.

Focus is not the selected entity. Preserve each pane's navigation state keyed by `(view, entity ID, section)` only for the current entity per view; reset detail offsets on entity change rather than retaining an unbounded map. Activity and Logs selection use message IDs, never vector positions. On refresh/filter/eviction keep an existing selected ID; if gone, select the nearest surviving position and clamp. Follow-tail pins to newest only while explicitly active; Up/Home/PgUp exits tail, End re-enters it. Wheel-up exits tail; wheel-down reaching the final item does not silently re-enable it.

Mouse focus is resolved from the last valid rendered hit map. Whole-pane zones include empty whitespace; row/section/action zones override them. Wheel changes only the hovered pane and focuses it, never a list elsewhere. Preserve stale-map invalidation, press/release stable-ID pairing, and the existing per-frame wheel budget. A modal swallows background hits. Focus is shown by the existing Amber token on the active section label and a textual marker, not color alone.

Rejected: one `detail_focused: bool` cannot distinguish sections; overloading entity selection with focus moves the wrong row; using only mouse hover makes keyboard position unstable; keeping Tab as view switching leaves no conventional pane traversal. A general pane tree is unnecessary.

### D2. One navigation helper and one page-size contract

B0 owns a pure helper in `navigation.rs` (or an equivalently small private module) reused by all sections:

`navigate(state: &mut ScrollState, action: NavAction, metrics: ScrollMetrics)`.

`NavAction = Up | Down | PageUp | PageDown | Home | End`; wheel maps to bounded repeated Up/Down. `ScrollMetrics` has `items`, `viewport_rows`, and `mode = Selectable | Text`. `ScrollState` has `selected: Option<usize>` and `offset: usize`; IDs remain the caller's responsibility. All arithmetic is saturating `usize`, with checked/clamped conversions only at the final ratatui coordinates. Never cast a long document offset to `u16` for `Paragraph::scroll`; render a sliced window.

- For a selectable list of N entries, selected is None if N=0, otherwise in `0..N`. Up/Down step one. PgUp/PgDn move `max(1, H)` entries. Home selects 0; End selects N-1. Clamp offset to `0..N.saturating_sub(H)` and minimally move it to keep selected visible when H>0.
- For text containing N **visual rows**, Up/Down change offset by one; pages by `max(1,H)`; Home offset=0; End offset=`N.saturating_sub(H)`. Text need not have a selected row.
- H=0 makes all navigation inert after clamping selection to valid data; do not fabricate a visible row or consume a non-existent pane. Zero-height panes are excluded by D1.
- Table section dividers are rendered chrome, not selectable entries. Each layout supplies the actual visible item capacity after headers/dividers. Keep the existing task-row mapping between grouped display rows and task/pseudo-row selections; the helper does not infer task indices from screen y. Pseudo rows such as Add Task remain selectable with their existing actions.

The renderer/layout is the sole authority for `viewport_rows`: the actual body rectangle after labels, section rail, borders, filter chips, footer, toasts and undo banners. A scroll indicator uses reserved footer space and never conditionally steals a data row. Publish metrics with frame generation and stable pane key alongside hit geometry; keys and wheel use that snapshot. On resize/layout change invalidate it, redraw before using geometry, and reclamp. In unit tests supply metrics directly.

Apply to main Goals/Tasks/Agents/Actions, Activity, all D1 detail sections, viewer, pickers, wizard option lists and command suggestions. Existing textarea and text input keep their library's editor cursor/Home/End semantics; page height and wheel forwarding use their rendered content rect. Do not replace editable text behavior with list arithmetic. Share the pure clamping/page-delta functions across adapters rather than creating another arithmetic implementation in each input path.

Rejected: hard-coded page size 10 fails split/resize; terminal height includes non-content rows; independent key/wheel arithmetic diverges; using ratatui TableState alone does not handle text, pane focus or existing hand-drawn/grouped lists. Ratatui provides rendering state, not a complete application focus/page contract.

### D3. Immutable full-text viewer overlay

Add `widgets/text_viewer.rs`; keep this read-only and independent from the editor. The shared `ViewerDocument` contract contains `source: ViewerSource`, `title: String`, `body: Arc<str>`, `completeness: Complete | Unavailable { reason: String }`, and `original_bytes: usize`; unavailable bodies carry an empty body and a visible reason. `ViewerSource` is either `Message(u64)` or `Entity { kind: EntityType, id: String, field: String }`. Strings never supply terminal-control framing. A document identifies its exact source, immutable body, and completeness/source size. Copy the entity field once on open; share retained message body bytes where possible. Freeze document content during arrival, eviction and entity refresh; only an explicit reopen observes new content.

Open with Enter on an Activity row, Actions row, detail activity/message line, or a focused text section (Description, Role, Result, Progress, Error, log Body). A single valid click on those text lines opens the same viewer after selecting/focusing the source; clicking blank body space just focuses. Entity main-row Enter/click keeps existing entity-detail opening. Structured table rows keep existing navigation actions. On Actions, Enter/click now opens the full viewer directly; `d` opens the Metadata/Body inspector so the log detail focus contract remains reachable. Error messages and legacy records with no detail use the full `Message.text` as body.

Show raw source text by default, including complete provider JSON when that is what was received. Do not substitute a truncated summary or generate an expanding pretty-printed JSON copy. Human message events without an envelope retain their original multiline body. Header shows source, byte count and any producer/TUI incompleteness notice. Esc closes viewer and restores prior focus/selection/offset (or a valid fallback if source was removed); q closes viewer, it does not quit the app. All other background entity actions are swallowed while open.

Up/Down/PgUp/PgDn/Home/End and wheel use D2. Long lines wrap at grapheme boundaries without trimming whitespace. Tabs expand to 4-column stops; empty lines and trailing newline remain represented. Combining marks, emoji/ZWJ sequences and wide CJK characters must not be split. Use the existing Unicode crates and ratatui widgets. Cache only the current document's visual-row start byte offsets and visible rows; do not allocate one object per character. Reflow once on width change and retain the top source-byte anchor.

Mouse selection is in-app: left down in text anchors a source byte boundary, drag extends, release freezes a half-open selection. Drag outside the body clamps to its nearest edge; no timer-driven auto-scroll is required. Wheel/keyboard scrolling during a drag or an established selection preserves source-byte anchors; subsequent dragging extends to newly visible text. Map visual grapheme cells (including expanded tabs and control-character placeholders) back to original byte ranges; select a whole grapheme/control placeholder if clicked in its trailing cell. Reverse selections normalize. Copy preserves original newlines and bytes, without soft-wrap newlines, padding or header text. Resize cancels an active drag but preserves an established selection. Lost mouse capture cancels drag. Stale frames never create a new selection.

**Shortcuts:** `Ctrl+Y` copies the entire current field/document; `y` copies only the nonempty selection in this read-only overlay, otherwise says “No selection — Ctrl+Y copies all”. A visible clickable Copy all/Copy selection footer offers the same operations. Ctrl+Y on a focused read-only detail text field opens/copies that complete field without requiring a prior viewer; on an Activity/Actions row it copies its complete body. In editors Ctrl+Y also means copy-all of the current field, replacing textarea's internal yank-paste binding; regular character y inserts y. Ctrl+Shift+C, if delivered distinctly, is an optional selection-copy alias, not the only keyboard path. This choice reserves ordinary text input, avoids Ctrl+C's interrupt expectation, and keeps a consistent copy-all key across read-only/editable surfaces. Clipboard errors remain visible without closing the viewer or losing selection.

Rejected: opening an external pager breaks mouse/backend consistency; growing every detail panel duplicates behavior; using a complete editable TextArea as the viewer would split the body into owned lines, normalize source line endings and use its internal u16 viewport; that does not meet the byte-preserving, usize-offset and 8 MiB index contract for a 1 MiB newline-heavy body. Reuse ratatui Paragraph and Unicode crates for rendering rather than an editor buffer; F2-only selection cannot copy off-screen content through the app. No new editor is being hand-written: this widget is a document renderer and source-span selection adapter over existing Unicode/rendering primitives.

### D4. Full retention with explicit resource limits

Remove the canonical `MAX_DETAIL_LEN=2048` truncations in both `messages/format.rs::cap_detail` and `Message::with_detail`. Remove fixed 200-character truncation from text used as the **canonical full message**; keep concise one-row previews as derived display values. `first_line_trunc` may remain for preview classification/labels, but its output must never be the only surviving body. Formatters retain original raw payload plus an uncapped human-text source where available, with one canonical copy or shared spans rather than duplicate full allocations. Panels may ellipsize visually; viewer resolves the original field before `cap_line`, `cap_text`, or the 10,000-character panel cap.

Preserve existing `summary: None` exclusions (e.g. reasoning-only events); no new sensitive-event ingestion policy. Existing human message/prompt records that are displayed must retain the entire received body. Do not change the engine's send-message size contract or any on-disk/peer format in this task.

Hard limits (new local memory policy, not measured usage):

- Maximum canonical message/document body: **1 MiB UTF-8 bytes**. Reject larger retained payloads as a whole and store a small explicit “Body unavailable: exceeds 1 MiB” record with original byte count/source, not a misleading truncated body. Do not emit a giant allocation merely to format the rejection. Copy-all is disabled for that unavailable body.
- Shared budget for pending + displayed message text/detail allocations: **32 MiB**, and existing **500-entry limits** on each collection. Count every owned text/detail allocation once, including previews and agent/task ID strings; share immutable body storage where possible. Admit newest live data by evicting oldest complete records; history prepends must evict older history before newer live records. Check raw payload byte length before JSON parsing/summary extraction in the formatter, and enforce budgets while consuming inputs, not after collecting an arbitrary history batch or flush clone. Overflow counts are visible in the feed footer.
- Viewer can pin **one additional 1 MiB** document after its source record is evicted. Row-offset index has an explicit **8 MiB** cap (at most one offset per source byte on 64-bit, with a trailing empty-row sentinel represented implicitly); render only a visible window. No O(character-count) vector of owned graphemes or full duplicate display string. Control-escape expansion is generated only for visible rows.
- The message-cache + viewer-body + index portion is thus bounded by **41 MiB**; draft payloads add at most 2 MiB and native copy request payloads at most 2 MiB. These are component bounds, excluding fixed row metadata, temporary incoming backend strings, loaded domain entities, existing history/backend queues, library-owned native clipboard allocations and allocator overhead. This is not a claim that whole-process RSS is 41 MiB. Backend history/event queue bounds are a separate pre-existing concern, not silently fixed by the retention budget.

B1 supplies budgeting/retention helpers in `messages/**`; B0 applies them at `state.rs::add_message`, `flush_messages`, and `prepend_messages`, without bulk cloning full strings. Pending/live limits count together, including during transfer. One incoming bounded document may be inspected before admission. For comparison/dedup, canonical full body participates: two events sharing a 200-character prefix but with different suffixes must both survive (`state.rs::repeats_latest` currently compares only summary text).

Rejected: merely raising 2 KiB to 50 KiB fails the next larger message; 500 unbounded strings is not a memory bound; per-character truncation silently reintroduces the reported data loss; a disk viewer cache creates a storage contract and is unnecessary at current scale. Limits are whole-record admission/eviction with honest notices. Upstream-shortened text is labeled when upstream supplies such metadata; do not claim recovery of missing bytes.

### D5. Clipboard port, native write and terminal/browser fallback

Extend the **TUI backend facade**, not `orch-core` frozen ports:

- `fn copy_text(&mut self, text: &str) -> BackendResult<CopyTicket>` queues one request, returning Busy/TooLarge/Unsupported synchronously if it cannot be accepted.
- `fn poll_copy_results(&mut self) -> Vec<CopyResult>` drains completion notifications; `CopyResult` carries ticket and `NativeWritten | TerminalRequested | Failed(String)`.
- Both types live in `backend/mod.rs`; fake backend records exact requested text and deterministic outcomes. TUI calls these through B1's input/tick hook, never directly calls arboard or prints to stdout.

Infra owns native text write using existing arboard. One bounded worker/queue (one in flight, one pending; no unbounded spawn-per-copy) retains the clipboard handle for the TUI backend lifetime, important for Linux ownership. Keep at most two completion records, and do not accept more work until their tickets are drained. Worker owns the handle on its own thread; native write does not block the render loop. Return/cancel the UI request after **3 seconds**, but do not claim that timeout can kill a stuck OS call: an occupied worker is not replaced and further native requests fail Busy; bounded queue and session-scoped lifecycle prevent runaway workers. Session shutdown signals the worker and never waits indefinitely to join it. The current process can terminate a stuck OS call; no immortal external helper is introduced. On uncertain native timeout report failure rather than a delayed second destination write. Immediate native unavailability/error may fall back to OSC 52.

Routing: local macOS/Linux tries native first; SSH sessions and explicitly marked web PTYs use terminal mode first, since successful server-local arboard would target the wrong person's clipboard. CLI launch context selects this via SSH environment and `ORCH_TUI_CLIENT=web` (I1 adds marker at the web PTY spawn). These are routing hints, not authorization. A copy requires an explicit key/footer gesture; never on arrival, focus, opening a document or selecting text.

OSC 52 write format is **fixed** `ESC ] 52 ; c ; BASE64(UTF8_BODY) BEL`. Use an existing base64 crate (already present in workspace) through approved dependency wiring, not a homemade encoder or shell command. Only ASCII base64 may occupy payload position; the selection parameter and terminator are constants. Raw ESC, BEL, ST, semicolons, newlines or agent-supplied labels never enter framing. No OSC queries/reads and no automatic tmux passthrough wrappers. Cap decoded terminal copy at **64 KiB** (base64 output <=87,384 bytes); larger copy requests show an explicit terminal-limit error with selection guidance, never partial success. Native copy supports the full admitted 1 MiB. Write one serialized sequence using the terminal output lock, outside ratatui's text renderer. On an I/O failure after a partial write, attempt a constant BEL terminator before reporting failure; never append source text while recovering the terminal parser. TerminalRequested means “Copy requested from terminal”, not “Copied”; terminal clipboard permission is not acknowledged by this protocol.

Do not feed untrusted terminal control bytes into ratatui spans on any expanded read surface, including source titles, IDs and footer errors. Render C0/C1/DEL controls visibly (except layout newline/tab); clipboard transport may contain original control bytes safely *inside base64*. Selection geometry maps placeholders back to the original bytes. A viewer footer can identify control-containing text; do not remove or execute it.

**Browser requirement / ownership:** current `orch web` has no OSC52 consumer. I1 must add a bounded, write-only `registerOscHandler(52, ...)` in the first-party `index.html`, accepting only `c;` plus strict base64, rejecting queries and payloads above 64 KiB after decoding. Decode UTF-8 strictly and place pending content in memory. Show a Copy to clipboard button/status; its click calls `navigator.clipboard.writeText` under a browser user gesture. On insecure HTTP or denied permission show a selectable text fallback and clear error. Never claim browser clipboard success at terminal-request time; no new WebSocket control protocol is needed. Do not edit vendored xterm.js. Clear pending clipboard content after use/session disconnect or a replacement request. Keep browser buffer capped at one payload. Browser confirmation is necessary because asynchronous terminal output may lack browser user activation.

Mac native success is required in manual QA; headless unit tests never read or overwrite the tester's real clipboard. Linux: test fake success/failure and manual X11/Wayland if available; report environment-specific limitations. SSH/terminal and web behavior need their own smoke cases; OSC support must not be assumed from TERM alone.

Rejected: OS shell tools duplicate arboard and create interpreter surfaces; native-only copies server clipboard remotely; OSC-only depends on emulator policy; arboard from `orch-tui` breaks the facade direction; fire-and-forget success lies on blocked terminals; relying on xterm.js core without a handler leaves browser copy broken.

### D6. Guard dirty transitions and keep memory drafts

B2 owns wizard session state and exit policy. Do not reuse `Wizard.dirty`: it currently governs validation and is not a semantic whole-form baseline. Capture initial **effective values** after edit/default prefills; compare normalized field values plus attachments and live current-step buffer, including values not yet advanced into `Wizard.values`. Ignore cursor, selection, scroll, validation timers and navigation. Normalize CRLF to LF, and ignore only the same outer whitespace that the existing submission path trims; preserve interior whitespace/newlines. A reverted edit is clean. Dynamic catalog/default refreshes are not user edits; capture effective defaults when each step first opens, and compare active fields plus retained user-entered fields rather than treating untouched skipped defaults as changes. A new form left empty/default is clean; explicitly changed choices/attachments are dirty.

Every user path that would replace current step, close/replace the wizard, or quit with a wizard active goes through `request_leave(LeaveIntent)` before mutating buffers: Esc, empty-field Backspace that goes back, footer Back, Cancel, shop replacement, and any actual quit route. Normal forward validation/submission remains forward flow. Dirty step back requires confirmation even though we can preserve the buffer; show “Leave this step? Unsaved input will be kept as a session draft.” Dirty cancel/exit shows “Leave editor? Keep a draft for this session or discard it.” Dialog defaults to **Continue editing**; options are Continue editing / Keep draft and leave / Discard and leave. Keyboard and mouse use the same transition operation; Esc in the dialog means Continue editing. Background actions and repeated clicks are swallowed while pending. Clean exits proceed immediately.

A draft captures all answered fields, the current unsubmitted field, step ID, selection/checkbox values, target/template/setting identity, attachments, and cursor position. Save a per-step scratch value before moving back so forward navigation restores it. Draft key is `(WizardKind, target_id?, setting?, template_key?)`, not kind alone: a Task draft must not overwrite EditTask or another entity's edit. For new forms, one draft per kind; for edits, one per kind+target. Restore automatically on reopening the exact key with a visible “Session draft restored” label. Baseline remains the originally opened entity/default state, so restored changes remain dirty until successfully submitted.

Use at most **20 drafts / 2 MiB total / 256 KiB per draft**, including text and attachment-path metadata; do not silently evict unsaved drafts. If full, leave the active editor open and offer Continue editing or explicit Discard; saving fails loudly until an old draft is submitted or deliberately discarded. Large live edits may still be submitted, but cannot be promised as saved drafts. Successful backend submission clears that draft; validation/backend failure preserves it and the active editor. Explicit Discard clears that key. Memory drafts disappear at application exit and never write an on-disk file.

For actual application quit, do not offer “Keep draft and quit” as durable safety: drafts die with the process. Offer Continue editing or explicit Discard and quit. A dirty retained draft also triggers this warning even if no wizard is currently open. Reopening an edit whose target was deleted or whose source values changed does not overwrite fresh data: expose the old draft in a read-only recovery viewer and require explicit restart/discard before submission; show that its baseline is stale. This is not a persisted revision protocol.

Mouse drag selection in the editor uses existing textarea selection/cursor APIs (`start_selection`, `selection_range`, `CursorMove`, `yank_text`); no new editor buffer. Use the verified `TextArea::cursor_at_position(Position)` API in the locked 0.13.2 (`src/widget.rs:281`) against its most recent valid render; it already handles wrapping, tabs, scrolling, line numbers and wide characters. Do not replicate its private viewport math. Apply the resulting position with the library cursor/selection operations; clamp outside drags to the editor body. Ctrl+Y copies the entire current field through D5; explicit Copy selection footer copies the library's selected range without deleting it or changing undo history. Selection-only actions never mark the form dirty. Single-line fields use the same grapheme-aware mapping through existing `TextInput` utilities. Ordinary y remains text. F2 remains available.

Rejected: confirmation only on first-step Esc misses back/replace paths; only disk drafts contradict selected scope and introduce secrets/storage policy; relying on a touched boolean prompts on cursor motion and loses reverted-edit semantics; saving a Wizard with closure-bearing config as disk JSON is not a valid draft format.

### D7. Vim feasibility: defer migration, use edtui if commissioned

**Recommendation: defer optional Vim in this QoL change; do not hand-roll a modal editor now.** This does not block safe editing, mouse selection or copying.

Evidence checked 2026-10-16:

- Cargo.lock pins ratatui 0.30.2 / core 0.1.2 / widgets 0.3.2 and tui-textarea-2 0.13.2. The installed textarea crate includes a substantial `examples/vim.rs` with Normal/Insert/Visual/Operator states; it is an example adapter, not a complete supported Vim mode.
- [edtui 0.11.7 release metadata](https://crates.io/api/v1/crates/edtui/0.11.7) reports MIT, not yanked, released 2026-08-16. Its downloaded published Cargo.toml requires ratatui-core ^0.1, ratatui-widgets ^0.3.0 and crossterm ^0.29; these ranges admit this lockfile. It has no declared `rust-version`; actual pinned-toolchain compilation and transitive license/advisory checks remain **unverified**.
- [edtui documentation](https://docs.rs/edtui/0.11.7/edtui/) describes Vim/Emacs handlers, mouse support and selectable feature flags. Default features include arboard and syntax highlighting; a future integration must disable defaults and enable only mouse support, routing clipboard through D5 rather than silently invoking a second native path.
- `Wizard::textarea()` returns a concrete TextArea and wizard rendering depends on it; replacing it touches validation, cursor/scroll, paste and draft snapshots. A superficially compiling crate addition is not a working wizard migration.

If the lead elects to implement now, reopen this decision before B2: prove one compatible ratatui-core/widgets/crossterm graph under pinned Rust, cargo-deny clean, and all wizard validation/paste/draft vectors; write a load-bearing editor ADR; use edtui behind a session opt-in, preserving ordinary insert editing by default. Rejected: custom modal layer despite maintained fitting edtui violates AGENTS §4.8's library-first rule; claiming edtui incompatible with ratatui 0.30 would be factually wrong; immediate replacement makes optional work a critical-path regression risk. 1. B1: `crate::widgets::text_viewer::handle_ui_event(self, event)`.
   Signature: `pub(crate) fn handle_ui_event<B: TuiBackend, C: Clock>(app: &mut App<B, C>, event: &UiEvent) -> bool`.
2. B2: `crate::wizard::handle_session_event(self, event)`.

## Data flow and failure behavior

```text
backend output / history / entity field
       | canonical bytes + limits (D4); no display truncation as storage
       v
retained messages / entity model -- stable source IDs --> focus + sections (D1)
       |                                             |
       +-------- Enter / click / Ctrl+Y --------------+
                             v
                    immutable viewer (D3)
                    wrap index + byte selection
                             |
                      explicit copy gesture
                             v
                 TuiBackend::copy_text (D5)
                   /                    \
            local native worker      SSH / web / unavailable-native
                 arboard             fixed OSC52 + base64
                   |                         |
             NativeWritten             TerminalRequested
                                    browser handler + click
                                    browser success/failure
```

```text
editor value/attachment change -> semantic comparison with original baseline
              |
     Back / Esc / Cancel / replacement / quit
              |
        clean? +-- yes --> apply transition
              |
              no
              v
     confirm (default Continue editing)
         |            |                    |
       Continue    Keep draft + leave    Discard + leave
       no change   bounded RAM snapshot  erase that draft
                   restore on reopen

Actual app quit: Continue OR explicit discard; RAM drafts cannot survive quit.
Submit failure: keep form + draft. Submit success: clear that draft.
```

| New path | Realistic failure | Required handling / test | What operator sees |
|---|---|---|---|
| Focus on refresh | Selected entity/message disappears | Reconcile by ID, clamp/fallback; F3/F4 | Valid nearby selection or closed detail |
| Page / wheel | Zero body height, last short page | Saturating D2 math; N1–N5 | No jump into hidden/invalid rows |
| Open viewer | Body evicted or too large | Resolve by ID; unavailable body state; V3/R2 | Explicit unavailable notice, never another row's text |
| Wrap/selection | Wide glyph, resize during drag | Byte-boundary mapping/cancel active drag; V2/V4 | Stable selected text, no split UTF-8 |
| Retention | Huge history batch/exhausted budget | Incremental admission/whole-record eviction; R1–R3 | Eviction count / oversized-body notice |
| Clipboard | OS stalls/unavailable, terminal drops request | Bounded worker / honest completion; C1–C4 | Failure, Busy or unacknowledged request |
| Browser copy | Handler absent, permission/insecure context | I1 handler + explicit button/fallback; C5 | Browser-local status, not false TUI success |
| Wizard leave | Current buffer not committed to Values | Snapshot live buffer first; E1–E5 | Confirmation and restorable field |
| Draft restore | Target changed/deleted, draft store full | No blind submit/no eviction; E6–E8 | Recovery viewer or keep-editing error |

All these paths require both a regression test and visible handling. A failure that is silent and has neither is a release blocker. No prompt/model behavior changes are planned, so no LLM eval suite is added.

## Trade-offs, risks and scaling limits

This design optimizes for predictable inspection and recovery at existing single-operator scale. The section rail gives independent detail focus at small sizes while showing fewer sections simultaneously. Immutable viewer snapshots intentionally require reopening to see changed content. Local memory limits can evict old records; they preserve complete admitted bodies rather than pretending every event remains forever. Disk/producer history is not modified and a future full-history browser is separate work.

The most likely integration failures are bypassed dirty guards via old mouse routes, key handlers bypassing the shared dispatcher, display-width/byte-coordinate confusion, and clipping before the viewer resolves its source. The test vectors directly target them. Clipboard timing cannot guarantee underlying OS cancellation; the bound is worker count/queue and UI wait, not an impossible killable synchronous call. Browser secure-context limitations and terminal policies are visible limitations. Full-process history buffering remains a potential pre-existing memory cost, explicitly outside the new retained-cache bound.

## NOT in scope / non-goals

- Persisted drafts, migrations, encryption/cleanup policies: user selected RAM only.
- Full Vim migration or a custom incomplete Vim engine: optional and not a cheap, verified fit (D7).
- Search, syntax highlighting and editable logs: not needed to read/select/copy full text.
- Changing message-service send caps, agent wire/peer schema or reconstructing upstream-truncated events: separate contracts owned outside TUI.
- Whole-app table framework, general pane docking and multiple simultaneous viewers: no demonstrated need.
- Terminal clipboard queries, automatic OSC tmux passthrough, background clipboard synchronization: unnecessary capability and portability risk.
- Unbounded history/archive viewer or a guaranteed whole-process RSS cap: existing backend/domain allocations require separate evidence.
- Publication, release or production configuration changes: not authorized by this design task.

Potential follow-ups proposed to the lead, not appended to a non-existent TODOS.md: (1) commission edtui migration if modal editing remains valuable after safe-editing QA; starts at D7's dependency probe and requires ADR, (2) profile existing history/backend queue retention if measured RSS exceeds the new cache's expected allocation budget. The second is conditional evidence-gathering, not speculative infrastructure work. Neither blocks the non-Vim QoL implementation.

## Rollback / compatibility

No on-disk, CLI or peer format changes. RAM drafts/viewport state die with the process, so reverting UI code needs no migration. Clipboard backend trait changes are internal and require FakeBackend plus CLI implementation to change together. New dependency/architectural ADR is written by the hot-file owner before adoption, never by silently editing frozen core ports. If browser clipboard glue is rolled back, disable the web copy affordance and show Unsupported; do not target the host clipboard. Reverting viewer/focus implementation restores prior Tab behavior, which must be reflected in help/docs. Existing config, running agents and historical files remain intact.
