## Goal

An operator can reach every list and detail section with keyboard or mouse, read a complete retained message or description, copy all or selected text, and leave an editor without silently losing changes. Preserve the existing terminal dashboard and its narrow backend facade. The user's selected draft policy is memory only. This document specifies future behavior; the features have not been implemented or exercised.

## Scope challenge and alternatives

Three approaches were considered:

- **A — shared renderer inside panels, optional expansion:** valid code reuse; in-place scrolling and copy-all are retained. Universal in-place range selection would add geometry/state integration to every panel and is deferred. The shared viewer is an explicit expansion for long messages and range selection, not the mandatory cost of focusing a panel. A panel-only solution still lacks space for complete feed records at narrow sizes.
- **B — explicit focus + common read-only viewer + existing editor (recommended):** reuses layout, hit map, backend, Unicode and textarea libraries; changes only the interaction surfaces that lose information.
- **C — new pane framework and replacement editor throughout:** cleaner theoretical uniformity, but introduces unrelated UI migration and dependency risk; rejected for the actual workload.

More than eight files are necessarily affected because input, rendering, backend I/O and editor transitions already live in separate modules. Reduce scope by retaining those modules, adding one viewer widget and one small pure navigation helper, and deferring optional Vim. Do not add a focus framework, async UI framework, search subsystem or new persistence format. Browser clipboard glue is required and owned by I1 (D5/D9); the lead must include it in integration acceptance.

## Design

### D1. Explicit focus, separate from entity selection

Add `Focus` in `state.rs` with these variants (nested section enums keep the boundary exhaustive):

- `MainList`, `Activity`, `GoalDetail(GoalSection)`, `TaskDetail(TaskSection)`, `AgentDetail(AgentSection)`, `LogDetail(LogSection)`, `TextViewer`.
- `GoalSection = Overview | Description | Progress | Tasks`.
- `TaskSection = Overview | Attachments | Description | Result | Files | Activity`.
- `AgentSection = Overview | Error | Role` (role is the agent's description; overview includes stats, current task, model/command and team information).
- `LogSection = Metadata | Body`.

Every existing detail datum belongs to one section. Empty Description/Role sections remain reachable with an explicit empty state. Optional absent Progress, Error, Attachments, Result, Files and Tasks sections are omitted from the ring; an existing but empty table still renders its empty state. A missing entity closes its detail and restores main focus.

Normal screen ring: `MainList -> Activity -> MainList`; Actions has only `MainList` until its inspector is open; B0 explicitly allocates a lower inspector region in that state (the current Logs layout otherwise reserves no feed height). With details open, replace Activity by the entity's sections in the order above. `Tab` cycles forward, `Shift-Tab`/BackTab backward and wraps. `Left/Right` retain top-level view switching when no detail is open; G/T/A/L retain existing conflicts and capability rules. Document that Tab now moves pane focus, replacing its former top-level-tab behavior. With a one-pane ring it remains on that pane (including Actions without inspector); help explicitly says “Tab: next pane; Left/Right: view”. Avoid a context-dependent Tab fallback that switches views only on one screen. Input/wizard/picker Tab keeps its current meaning.

Render detail sections through a compact section-name rail plus **one section body at a time** in the existing lower rectangle. This is deliberate: at 40x14 there is no useful room for six independently scrollable stacked panes. Tab can reach every available section even when its label is elided; active title is always visible. Mouse on a section label selects that section. Clicking or wheeling in its body focuses it. At larger sizes pin a two-row Overview summary (entity name/status, agent/run/retry or progress context as applicable) above a non-Overview body whenever at least four body rows remain after rail/footer/summary. At smaller sizes omit the pin. The pin is read-only chrome, not a second cursor; clicking it focuses Overview. Subtract its rows from D2 metrics. This preserves identity/status context without introducing multiple independently laid-out section bodies. A maximized detail excludes the zero-height MainList from the ring. Empty ring / too-small screen yields a safe MainList fallback without attempting navigation.

Focus is not the selected entity. Preserve each pane's navigation state keyed by `(view, entity ID, section)` only for the current entity per view; reset detail offsets on entity change rather than retaining an unbounded map. Activity and Logs selection use message IDs, never vector positions. On refresh/filter/eviction keep an existing selected ID; if gone, select the nearest surviving position and clamp. Follow-tail pins to newest only while explicitly active; Up/Home/PgUp exits tail, End re-enters it. Wheel-up exits tail; wheel-down reaching the final item does not silently re-enable it. Keyboard Down when already on the final Logs row re-enters tail, preserving the existing behavior. Activity has the same explicit End/Down-at-final rule. Arrival while not following retains the selected ID and viewport anchor.

Entity-action letter bindings (`a c d e p r s u x m` where registered) are enabled only in MainList. Every detail section, including Goal Tasks and Task Activity, is inspection-only for these letters: a row selection there never redirects an action silently to the parent entity. Return focus to MainList to edit/mutate. Normal-mode letter bindings accept only empty or SHIFT modifiers; CONTROL, ALT, SUPER, HYPER and META variants are ignored after explicitly recognized shortcuts have been handled. Ctrl+C and Ctrl+Shift+C never mutate an entity. No Ctrl+Shift+C copy alias is introduced. Viewer/editor copy shortcuts are dispatched before this guard. Existing picker/wizard/command modes continue to swallow global actions.

Mouse focus is resolved from the last valid rendered hit map. Whole-pane zones include empty whitespace; row/section/action zones override them. Wheel changes only the hovered pane and focuses it, never a list elsewhere. Preserve stale-map invalidation, press/release stable-ID pairing, and the existing per-frame wheel budget, counted in accepted notches rather than resulting rows. No timed target latch: each accepted wheel event resolves its current hovered pane. Crossing a pane boundary changes focus and the scrolling target; the active border/title immediately identifies it. This consciously favors the user’s stated hover-wheel contract over guessing physical momentum from events that carry no gesture identifier (C1-11). A modal swallows background hits. Focus is shown by the existing Amber token on the active section label and a textual marker, not color alone.

Rejected: one `detail_focused: bool` cannot distinguish sections; overloading entity selection with focus moves the wrong row; using only mouse hover makes keyboard position unstable; keeping Tab as view switching leaves no conventional pane traversal. A general pane tree is unnecessary.

### D2. One navigation helper and one page-size contract

B0 owns a pure helper in `navigation.rs` (or an equivalently small private module) reused by all sections:

`navigate(state: &mut ScrollState, action: NavAction, metrics: ScrollMetrics)`.

`NavAction = Up | Down | PageUp | PageDown | Home | End`; wheel maps to bounded repeated Up/Down: one selectable entry per notch for lists, three visual rows per notch for read-only text. B2 adapts editor wheel to three visual rows through its viewport API. Keep the existing maximum three accepted notches per frame, so text can advance nine rows per frame without unbounded backlog. `ScrollMetrics` has `items` (selectable count), `display_rows` (total drawn rows including group headers), `viewport_rows`, `selection_rows: &[usize]` (strictly increasing selection-index → display-row map), and `mode = Selectable | Text`. Ungrouped rows use the identity map; Text ignores selection fields. `ScrollState` has `selected: Option<usize>` and `offset: usize`; IDs remain the caller's responsibility. All arithmetic is saturating `usize`, with checked/clamped conversions only at the final ratatui coordinates. Never cast a long document offset to `u16` for `Paragraph::scroll`; render a sliced window.

- For an ungrouped selectable list of N entries, selected is None if N=0, otherwise in `0..N`. Up/Down step one and minimally reveal. PgUp/PgDn independently advance both selected and offset by H, clamped at their own bounds; this preserves the selected screen row until an end clamp. Home sets (0,0); End sets (N-1, N.saturating_sub(H)). Always reveal selection after clamping.
- For grouped lists, offset is **display rows**, selected remains a selectable index. Let R=display_rows and r=selection_rows[selected]. Up/Down choose adjacent selectable indices then minimally reveal their display row. For a page set target row=clamp(r±H,0,R-1), and offset=clamp(offset±H,0,R.saturating_sub(H)); choose the first selectable row at/after target for PageDown, or last at/before target for PageUp, falling back to the last/first selectable row at an endpoint. Then minimally reveal it. Headers count toward page distance but never become selected. Home selects first at offset0; End selects last at offset=R.saturating_sub(H).
- For text containing N **visual rows**, Up/Down change offset by one; pages by `max(1,H)`; Home offset=0; End offset=`N.saturating_sub(H)`. Text need not have a selected row.
- H=0 makes all navigation inert after clamping selection to valid data; do not fabricate a visible row or consume a non-existent pane. Zero-height panes are excluded by D1.
- Table section dividers inside the scrolling body occupy display rows; top table headings outside that body are chrome subtracted from H. B0 derives selection_rows from `task_rows()` (and equivalent grouped Agent rows) for both rendering and navigation. No estimate of “visible item capacity” may replace this map. Pseudo rows such as Add Task remain selectable with their existing actions. B0 corrects every writer of `task_scroll` to the same display-row unit, including refresh/reveal, not just PageDown.

The renderer/layout is the sole authority for `viewport_rows`: the actual body rectangle after labels, section rail, borders, filter chips, footer, toasts and undo banners. A scroll indicator uses reserved footer space and never conditionally steals a data row. Publish metrics with frame generation and stable pane key alongside hit geometry; keys and wheel use that snapshot. On resize/layout change invalidate it, redraw before using geometry, and reclamp. In unit tests supply metrics directly.

Apply to main Goals/Tasks/Agents/Actions, Activity, all D1 detail sections, viewer, pickers, wizard option lists and command suggestions. Existing textarea and text input keep their library's editor cursor/Home/End semantics; page height and wheel forwarding use their rendered content rect. Do not replace editable text behavior with list arithmetic. Share the pure clamping/page-delta functions across adapters rather than creating another arithmetic implementation in each input path.

Rejected: hard-coded page size 10 fails split/resize; terminal height includes non-content rows; independent key/wheel arithmetic diverges; using ratatui TableState alone does not handle text, pane focus or existing hand-drawn/grouped lists. Ratatui provides rendering state, not a complete application focus/page contract.

### D3. Immutable full-text viewer overlay

Add `widgets/text_viewer.rs`; keep this read-only and independent from the editor. The shared `ViewerDocument` contract contains `source: ViewerSource`, `title: String`, `body: Arc<str>` (default representation), `representation: Human | Raw | Field`, `raw_body: Option<Arc<str>>` (only when the default is Human), `completeness: Complete | Unavailable { reason: String }`, `original_bytes: usize` (received raw size), `captured_at_ms: i64`, and `initial_anchor: usize` (source byte boundary in the default body); unavailable bodies carry an empty body and a visible reason. `ViewerSource` is either `Message(u64)` or `Entity { kind: EntityType, id: String, field: String }`. Strings never supply terminal-control framing. A document identifies its exact source, immutable body, and completeness/source size. Copy the entity field once on open; share retained message body bytes where possible. Freeze both representations during arrival, eviction and entity refresh; only closing and explicitly reopening observes new content. Header always reads “Snapshot · captured <time> · <Human/Raw/Field> · <active byte count>”; footer says “Esc closes; reopen for latest”. Source changed/removed may be indicated when a cheap comparison exists, but no new revision service is required. Never automatically refresh or remap a selection onto new bytes.

Open with Enter on an Activity row, Actions row, detail activity/message line, or a focused text section (Description, Role, Result, Progress, Error, log Body). A single valid row click only selects/focuses; double-click or Enter explicitly expands that exact stable message ID. In already-open detail text bodies, single click focuses the section and records the clicked source-byte anchor; Enter or the visible Expand action opens the viewer. Double-click there may invoke the same expansion. Blank body space focuses without changing the anchor. Preserve existing entity main-row select/double-click/Enter behavior. On Actions Enter/double-click opens the full viewer; `i` opens the Metadata/Body inspector. No new `d` inspector binding is added.

Expansion passes the clicked anchor if one exists, otherwise the section's current top source-byte anchor, not a visual-row number. On opening, clamp to a grapheme boundary and place the visual row containing that byte at the top. Source changes between last frame and expansion invalidate the clicked anchor; resolve current source and use a clamped top anchor, never another source's text. Close restores the originating pane's independent selection/offset/focus; viewer scrolling does not rewrite those values. A removed source restores a valid fallback.

For recognized message/error envelopes, the default is the **complete decoded human message**, preserving its literal paragraphs, quotes and commands. Extract from the actual known schema fields used by existing formatters (including wrapped Codex item.completed/item.started → item.agent_message.text and existing provider text/error fields); never reuse their truncated summaries. Multiple text blocks retain order with a single newline separator and the label “Human (text blocks joined)”; unsupported/malformed schemas default to exact received Raw. Preserve current exclusions such as reasoning-only records. Plain messages use their exact original body. Missing legacy detail falls back to full Message.text with an honest legacy-source label where completeness cannot be known.

A visible Human/Raw toggle (keyboard `r` inside the modal) changes only representation, resets viewport/selection to start, and shows “Selection cleared: representation changed”. Switching never fetches new source. Copy always uses the labeled active representation: decoded bytes in Human, exact received bytes in Raw, exact field bytes in Field. Do not pretty-print or silently substitute a summary. Esc/q close the viewer, never quit; other background actions are swallowed. The immutable raw snapshot remains available after cache eviction within D4's revised pin bound.

Up/Down/PgUp/PgDn/Home/End and wheel use D2. Long lines wrap at grapheme boundaries without trimming whitespace. Tabs expand to 4-column stops; empty lines and trailing newline remain represented. Combining marks, emoji/ZWJ sequences and wide CJK characters must not be split. Use the existing Unicode crates and ratatui widgets. Cache only the current document's visual-row start byte offsets and visible rows; do not allocate one object per character. Reflow once on width change and retain the top source-byte anchor.

Mouse selection is in-app: left down in text anchors a source byte boundary, drag extends, release freezes a half-open selection. Drag outside the body clamps to its nearest edge; no timer-driven auto-scroll is required. Wheel/keyboard scrolling during a drag or an established selection preserves source-byte anchors; subsequent dragging extends to newly visible text. Add a keyboard selection caret initialized at initial_anchor: Left/Right move by grapheme, Shift+Left/Right/Up/Down extend the half-open range by grapheme/visual row, Shift+Home/End extend to the current visual row edge; unmodified Up/Down remain D2 scrolling. Plain scrolling with no selection places the caret at the new top source anchor; with an established selection it preserves the range; Ctrl+Home/End move the caret to document start/end, adding Shift extends there. Ordinary Home/End without modifiers retain D2 scroll semantics. Keep caret visible when it moves. This gives every mouse selection a keyboard path. Map visual grapheme cells (including expanded tabs and control-character placeholders) back to original byte ranges; select a whole grapheme/control placeholder if clicked in its trailing cell. Reverse selections normalize. Copy preserves original newlines and bytes, without soft-wrap newlines, padding or header text. Resize cancels an active drag but preserves an established selection. Lost mouse capture cancels drag. Stale frames never create a new selection.

**Shortcuts:** `Ctrl+Y` copies the entire current field/document; `y` copies only the nonempty selection in this read-only overlay, otherwise says “No selection — Ctrl+Y copies all”. A visible clickable Copy all/Copy selection footer offers the same operations. Copy via terminal explicitly selects the terminal route for the current selection, or the whole body when selection is empty; Ctrl+Alt+C is its keyboard equivalent, consumed only in viewer/editor/read-only focused text contexts and never interpreted as an entity action. Ctrl+Y on a focused read-only detail text field opens/copies that complete field without requiring a prior viewer; on an Activity/Actions row it copies its complete body. In editors Ctrl+Y also means copy-all of the current field (currently unbound by the app’s explicit dispatch); regular character y inserts y. Ctrl+Shift+C is deliberately unbound. Ctrl+Alt+Y copies the nonempty current selection in both viewer and editor; otherwise it reports “No selection”. This choice reserves ordinary text input, avoids Ctrl+C's interrupt expectation, and keeps a consistent copy-all key across read-only/editable surfaces. Clipboard errors remain visible without closing the viewer or losing selection.

Rejected: opening an external pager breaks mouse/backend consistency; universal in-place range selection would expand panel integration beyond this optional-expansion boundary; using a complete editable TextArea as the viewer would split the body into owned lines, normalize source line endings and use its internal u16 viewport; that does not meet the byte-preserving, usize-offset and 8 MiB index contract for a 1 MiB newline-heavy body. Reuse ratatui Paragraph and Unicode crates for rendering rather than an editor buffer; F2-only selection cannot copy off-screen content through the app. No new editor is being hand-written: this widget is a document renderer and source-span selection adapter over existing Unicode/rendering primitives.

### D4. Full retention with explicit resource limits

Remove the canonical `MAX_DETAIL_LEN=2048` truncations in both `messages/format.rs::cap_detail` and `Message::with_detail`. Remove fixed 200-character truncation from text used as the **canonical full message**; keep concise one-row previews as derived display values. `first_line_trunc` may remain for preview classification/labels, but its output must never be the only surviving body. Formatters retain original raw payload plus an uncapped human-text source where available, with one canonical copy or shared spans rather than duplicate full allocations. Panels may ellipsize visually; viewer resolves the original field before `cap_line`, `cap_text`, or the 10,000-character panel cap.

Preserve existing `summary: None` exclusions (e.g. reasoning-only events); no new sensitive-event ingestion policy. Existing human message/prompt records that are displayed must retain the entire received body. Do not change the engine's send-message size contract or any on-disk/peer format in this task.

Hard limits (new local memory policy, not measured usage):

- Maximum received raw message and each document representation: **1 MiB UTF-8 bytes**. Reject larger retained payloads as a whole and store a small explicit “Body unavailable: exceeds 1 MiB” record with original byte count/source, not a misleading truncated body. Do not emit a giant allocation merely to format the rejection. Copy-all is disabled for that unavailable body.
- Shared budget for pending + displayed message text/detail allocations: **32 MiB**, and existing **500-entry limits** on each collection. Count every owned text/detail allocation once, including previews and agent/task ID strings; share immutable body storage where possible. Admit newest live data by evicting oldest complete records; history prepends must evict older history before newer live records. Check raw payload byte length before JSON parsing/summary extraction in the formatter, and enforce budgets while consuming inputs, not after collecting an arbitrary history batch or flush clone. Overflow counts are visible in the feed footer.
- Viewer can pin **one snapshot with up to two 1 MiB representations (2 MiB total)** after its source record is evicted. Human and Raw allocations both count toward the 32 MiB retention budget while cached; share Arcs rather than cloning bytes on open. Only the active representation has a row index, destroyed before rebuilding on a representation switch. Row-offset index has an explicit **8 MiB** cap (at most one offset per source byte on 64-bit, with a trailing empty-row sentinel represented implicitly); render only a visible window. No O(character-count) vector of owned graphemes or full duplicate display string. Control-escape expansion is generated only for visible rows.
- The message-cache + viewer-body + index portion is thus bounded by **42 MiB**; draft payloads add at most 2 MiB and native copy request payloads at most 2 MiB. These are component bounds, excluding fixed row metadata, temporary incoming backend strings, loaded domain entities, existing history/backend queues, library-owned native clipboard allocations and allocator overhead. This is not a claim that whole-process RSS is 42 MiB. Backend history/event queue bounds are a separate pre-existing concern, not silently fixed by the retention budget.

B1 supplies budgeting/retention helpers in `messages/**`; B0 applies them at `state.rs::add_message`, `flush_messages`, and `prepend_messages`, without bulk cloning full strings. Pending/live limits count together, including during transfer. One incoming bounded document may be inspected before admission. For comparison/dedup, canonical full body participates: two events sharing a 200-character prefix but with different suffixes must both survive (`state.rs::repeats_latest` currently compares only summary text).

Rejected: merely raising 2 KiB to 50 KiB fails the next larger message; 500 unbounded strings is not a memory bound; per-character truncation silently reintroduces the reported data loss; a disk viewer cache creates a storage contract and is unnecessary at current scale. Limits are whole-record admission/eviction with honest notices. Upstream-shortened text is labeled when upstream supplies such metadata; do not claim recovery of missing bytes.

### D5. Clipboard port, native write and terminal/browser fallback

Extend the **TUI backend facade**, not `orch-core` frozen ports:

- `fn copy_text(&mut self, text: &str) -> BackendResult<CopyTicket>` queues one request, returning Busy/TooLarge/Unsupported synchronously if it cannot be accepted.
- `fn copy_text_via(&mut self, text: &str, target: CopyTarget) -> BackendResult<CopyTicket>` uses `CopyTarget = Auto | Terminal`; `copy_text` delegates with Auto. This is an additive proposed internal seam for the explicit terminal route, seeded in I0.
- `fn poll_copy_results(&mut self) -> Vec<CopyResult>` drains completion notifications; `CopyResult` carries ticket and `NativeWritten | TerminalRequested | Failed(String)`.
- Both types live in `backend/mod.rs`; fake backend records exact requested text and deterministic outcomes. TUI calls these through B1's input/tick hook, never directly calls arboard or prints to stdout.

Infra owns native text write using existing arboard. One bounded worker/queue (one in flight, one pending; no unbounded spawn-per-copy) retains the clipboard handle for the TUI backend lifetime, important for Linux ownership. Keep at most two completion records, and do not accept more work until their tickets are drained. Worker owns the handle on its own thread; native write does not block the render loop. Return/cancel the UI request after **3 seconds**, but do not claim that timeout can kill a stuck OS call: an occupied worker is not replaced and further native requests fail Busy; bounded queue and session-scoped lifecycle prevent runaway workers. Session shutdown signals the worker and never waits indefinitely to join it. The current process can terminate a stuck OS call; no immortal external helper is introduced. On uncertain native timeout report failure rather than a delayed second destination write. Immediate native unavailability/error may fall back to OSC 52.

Routing precedence: explicit Terminal always uses OSC; Auto uses OSC when `ORCH_TUI_CLIENT=web`, any SSH session hint, `TMUX`, or `STY` is present. Auto uses native-first only without these hints. A long-running multiplexer pane can have stale SSH variables, so TMUX/STY independently choose terminal delivery even for a locally-created pane later attached remotely. No implicit dual-write: it would put copied text on an additional host clipboard without establishing that this is the desired destination. The trade-off is that a local tmux user needs OSC support, subject to the same honest unavailable/requested status. Explicit Copy via terminal remains available even if launch hints are absent or misleading. Native success says “Copied on this host”; OSC says “Copy requested from terminal”; never a bare “Copied”. I1 adds the web marker at PTY spawn. These are routing hints, not authorization. A copy requires an explicit key/footer gesture; never on arrival, focus, opening a document or selecting text.

OSC 52 write format is **fixed** `ESC ] 52 ; c ; BASE64(UTF8_BODY) BEL`. Use an existing base64 crate (already present in workspace) through approved dependency wiring, not a homemade encoder or shell command. Only ASCII base64 may occupy payload position; the selection parameter and terminator are constants. Raw ESC, BEL, ST, semicolons, newlines or agent-supplied labels never enter framing. No OSC queries/reads and no automatic tmux passthrough wrappers. Cap decoded terminal copy at **64 KiB** (base64 output <=87,384 bytes); larger copy requests show an explicit terminal-limit error with selection guidance, never partial success. Native copy supports the full admitted 1 MiB. Write one serialized sequence using the terminal output lock, outside ratatui's text renderer. On an I/O failure after a partial write, attempt a constant BEL terminator before reporting failure; never append source text while recovering the terminal parser. TerminalRequested means “Copy requested from terminal”, not “Copied”; terminal clipboard permission is not acknowledged by this protocol.

Do not feed untrusted terminal control bytes into ratatui spans on any expanded read surface, including source titles, IDs and footer errors. Render C0/C1/DEL controls visibly (except layout newline/tab); clipboard transport may contain original control bytes safely *inside base64*. Selection geometry maps placeholders back to the original bytes. A viewer footer can identify control-containing text; do not remove or execute it.

**Browser requirement / ownership:** current `orch web` has no OSC52 consumer. I1 must add a bounded, write-only `registerOscHandler(52, ...)` in the first-party `index.html`, accepting only `c;` plus strict base64, rejecting queries and payloads above 64 KiB after decoding. Decode UTF-8 strictly and place pending content in memory. Show a Copy to clipboard button/status; its click calls `navigator.clipboard.writeText` under a browser user gesture. On insecure HTTP or denied permission show a selectable text fallback and clear error. Never claim browser clipboard success at terminal-request time; no new WebSocket control protocol is needed. Do not edit vendored xterm.js. Clear pending clipboard content after use/session disconnect or a replacement request. Keep browser buffer capped at one payload. Browser confirmation is necessary because asynchronous terminal output may lack browser user activation.

Mac native success is required in manual QA; headless unit tests never read or overwrite the tester's real clipboard. Linux: test fake success/failure and manual X11/Wayland if available; report environment-specific limitations. SSH/terminal and web behavior need their own smoke cases; OSC support must not be assumed from TERM alone.

Rejected: OS shell tools duplicate arboard and create interpreter surfaces; native-only copies server clipboard remotely; OSC-only depends on emulator policy; arboard from `orch-tui` breaks the facade direction; fire-and-forget success lies on blocked terminals; relying on xterm.js core without a handler leaves browser copy broken.

### D6. Guard dirty transitions and keep memory drafts

B2 owns wizard session state and exit policy. B0 owns normalized exit routing: all user q/Q, armed footer quit and `/quit` routes call `request_exit(ExitCause::User)`. Signals call `request_exit(ExitCause::Signal)` without waiting for confirmation; terminal loss/panic/I/O unwind remain immediate restoration paths. RAM drafts cannot survive forced shutdown, and no dialog claims otherwise. D9 defines how normalized exit requests enter the single B2 event hook; raw-key interception alone is insufficient. Do not reuse `Wizard.dirty`: it currently governs validation and is not a semantic whole-form baseline. Capture initial **effective values** after edit/default prefills; compare normalized field values plus attachments and live current-step buffer, including values not yet advanced into `Wizard.values`. Ignore cursor, selection, scroll, validation timers and navigation. Normalize CRLF to LF, and ignore only the same outer whitespace that the existing submission path trims; preserve interior whitespace/newlines. A reverted edit is clean. Dynamic catalog/default refreshes are not user edits; capture effective defaults when each step first opens, and compare active fields plus retained user-entered fields rather than treating untouched skipped defaults as changes. A new form left empty/default is clean; explicitly changed choices/attachments are dirty.

Every user path that would replace current step, close/replace the wizard, or quit with a wizard active goes through `request_leave(LeaveIntent)` before mutating buffers: Esc, empty-field Backspace that goes back, footer Back, Cancel, shop replacement, and any actual quit route. Normal forward validation/submission remains forward flow. Dirty step back requires confirmation even though we can preserve the buffer; show “Leave this step? Unsaved input will be kept as a session draft.” Dirty cancel/exit shows “Leave editor? Keep a draft for this session or discard it.” Dialog defaults to **Continue editing**; options are Continue editing / Keep draft and leave / Discard and leave. Keyboard and mouse use the same transition operation; Esc in the dialog means Continue editing. Background actions and repeated clicks are swallowed while pending. Clean exits proceed immediately.

A draft captures all answered fields, the current unsubmitted field, step ID, selection/checkbox values, target/template/setting identity, attachments, and cursor position. Save a per-step scratch value before moving back so forward navigation restores it. Draft key is `(WizardKind, target_id?, setting?, template_key?)`, not kind alone: a Task draft must not overwrite EditTask or another entity's edit. For new forms, one draft per kind; for edits, one per kind+target. Restore automatically on reopening the exact key with a visible “Session draft restored” label. Baseline remains the originally opened entity/default state, so restored changes remain dirty until successfully submitted.

Use at most **20 drafts / 2 MiB total / 256 KiB per draft**, including text and attachment-path metadata; do not silently evict unsaved drafts. If full, leave the active editor open and offer Continue editing or explicit Discard; saving fails loudly until an old draft is submitted or deliberately discarded. Large live edits may still be submitted, but cannot be promised as saved drafts. Successful backend submission clears that draft; validation/backend failure preserves it and the active editor. B2 owns `app.rs::submit_wizard` and all nine `submit_*` helpers: `submit_task`, `submit_edit_task`, `submit_agent`, `submit_edit_agent`, `submit_shop`, `submit_team`, `submit_goal`, `submit_edit_goal`, `submit_config`. Each returns an explicit submission outcome: Failed (keep form), Committed (clear matching draft), or Advanced (shop selection produced the next wizard; preserve that replacement rather than closing it). Invalid shop selection is Failed. Config must check the actual save_* result before changing local values or claiming “Settings saved”; bypass the old change_palette convenience method inside submit_config because it swallows persistence errors. The command-only palette path is outside this slice. Keep the original Wizard and pending attachments until the primary backend mutation succeeds; do not `take()` and drop either before the result. On a primary failure restore the exact active form/input mode/attachments and keep its draft, even when the draft store is full (retaining an active form is not a new saved draft). On success clear only that key and close. Missing required target/setting is a visible failure, not false success. If a primary create/update succeeded but a follow-up assign/team operation failed, report partial success with the created ID and do not retain a “retry create” form that duplicates the entity. Preserve the committed primary outcome and offer the existing explicit assignment/team path; do not invent automatic retries. Guard `open_task_wizard` before clearing attachments, plus all open/replace/config/shop/name-suggestion routes and catalog refresh so draft baselines remain valid. Explicit Discard clears that key. Memory drafts disappear at application exit and never write an on-disk file.

For actual application quit, do not offer “Keep draft and quit” as durable safety: drafts die with the process. Offer Continue editing or explicit Discard and quit. A dirty retained draft also triggers this warning even if no wizard is currently open. Reopening an edit whose target was deleted or whose source values changed does not overwrite fresh data: expose the old draft in a read-only recovery viewer and require explicit restart/discard before submission; show that its baseline is stale. This is not a persisted revision protocol.

Mouse drag selection in the editor uses existing textarea selection/cursor APIs (`start_selection`, `selection_range`, `CursorMove`, `yank_text`); no new editor buffer. Use the verified `TextArea::cursor_at_position(Position)` API in the locked 0.13.2 (`src/widget.rs:281`) against its most recent valid render; it already handles wrapping, tabs, scrolling, line numbers and wide characters. Do not replicate its private viewport math. Apply the resulting position with the library cursor/selection operations; clamp outside drags to the editor body. Ctrl+Y copies the entire current field through D5; explicit Copy selection footer copies the library's selected range without deleting it or changing undo history. Selection-only actions never mark the form dirty. Keyboard parity: Shift+Left/Right/Up/Down extends selection using the locked library’s public start_selection/cancel_selection/move_cursor APIs (or its public Input conversion). Its move_cursor_with_shift helper is private in 0.13.2 and must not be called directly; Ctrl+Alt+Y copies the selection. Bind Ctrl+Z to undo and Ctrl+R to redo only inside editable fields; Ctrl+U remains delete-to-line-head, Ctrl+K delete-to-line-tail, Ctrl+A/E move to line head/end, Ctrl+W deletes a word. Ctrl+R is not intercepted as Raw toggle in editor mode. Undo/redo recompute semantic dirty state. Single-line fields use the same grapheme-aware mapping through existing `TextInput` utilities, adding selection/history adaptation only inside B2’s text scope. Ordinary y remains text. F2 remains available.

Rejected: confirmation only on first-step Esc misses back/replace paths; only disk drafts contradict selected scope and introduce secrets/storage policy; relying on a touched boolean prompts on cursor motion and loses reverted-edit semantics; saving a Wizard with closure-bearing config as disk JSON is not a valid draft format.

## Trade-offs, risks and scaling limits

This design optimizes for predictable inspection and recovery at existing single-operator scale. The section rail gives independent detail focus at small sizes while showing fewer sections simultaneously. Immutable viewer snapshots intentionally require reopening to see changed content. Local memory limits can evict old records; they preserve complete admitted bodies rather than pretending every event remains forever. Disk/producer history is not modified and a future full-history browser is separate work.

The most likely integration failures are bypassed dirty guards via old mouse routes, key handlers bypassing the shared dispatcher, display-width/byte-coordinate confusion, and clipping before the viewer resolves its source. The test vectors directly target them. Clipboard timing cannot guarantee underlying OS cancellation; the bound is worker count/queue and UI wait, not an impossible killable synchronous call. Browser secure-context limitations and terminal policies are visible limitations. Full-process history buffering remains a potential pre-existing memory cost, explicitly outside the new retained-cache bound.

## NOT in scope / non-goals

- Persisted drafts, migrations, encryption/cleanup policies: user selected RAM only.
- Full Vim migration or a custom incomplete Vim engine in B0/B1/B2: dependency-fit probe is positive; safe wizard integration still requires the bounded follow-on decision/spike (D7).
- Search, syntax highlighting and editable logs: not needed to read/select/copy full text.
- Changing message-service send caps, agent wire/peer schema or reconstructing upstream-truncated events: separate contracts owned outside TUI.
- Whole-app table framework, general pane docking and multiple simultaneous viewers: no demonstrated need.
- Terminal clipboard queries, automatic OSC tmux passthrough, background clipboard synchronization: unnecessary capability and portability risk.
- Unbounded history/archive viewer or a guaranteed whole-process RSS cap: existing backend/domain allocations require separate evidence.
- Publication, release or production configuration changes: not authorized by this design task.

Potential follow-ups proposed to the lead, not appended to a non-existent TODOS.md: (1) commission edtui migration if modal editing remains valuable after safe-editing QA; starts at D7's dependency probe and requires ADR, (2) profile existing history/backend queue retention if measured RSS exceeds the new cache's expected allocation budget. The second is conditional evidence-gathering, not speculative infrastructure work. Neither blocks the non-Vim QoL implementation.

## Rollback / compatibility

No on-disk, CLI or peer format changes. RAM drafts/viewport state die with the process, so reverting UI code needs no migration. Clipboard backend trait changes are internal and require FakeBackend plus CLI implementation to change together. New dependency/architectural ADR is written by the hot-file owner before adoption, never by silently editing frozen core ports. If browser clipboard glue is rolled back, disable the web copy affordance and show Unsupported; do not target the host clipboard. Reverting viewer/focus implementation restores prior Tab behavior, which must be reflected in help/docs. Existing config, running agents and historical files remain intact.
