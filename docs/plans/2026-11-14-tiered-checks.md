blocking mode with the existing one-second read/write timeout: on macOS they can
inherit the listener's nonblocking mode and otherwise reject a valid client before
its bytes arrive. Delayed and fragmented challenges exercise the real holder;
invalid capabilities still grant nothing. Bootstrap and Rust source-name support differ:
the bootstrap encodes Git-quoted path bytes losslessly, while Rust judge capture
explicitly refuses unsupported control/non-UTF8 names. Such a run cannot qualify.

The whole-run producer reserves an IN PROGRESS report before admission, retains
step logs/inventory/environment names/tool versions and real command statuses,
and atomically publishes the final result. It keeps the ten latest completed,
validated run directories, preserving pending and unknown entries. The complete
marker denotes report completion, never a passed suite. A consistent inventory
helper may return zero with failed rows; the actual suite's exit and those rows
still fail the test step. Partial exports are nonqualifying and return 3 when
otherwise passing. A clean real full/pr run must establish all predicate fields,
the exact judge/commit/tree, pinned tools, default live lease and finished target.
A direct invocation without a matching stamp at the fixed bootstrap executable
path remains nonqualifying even if every check passes.

A run-wide sticky listener stays alive through reporting. After a handled signal,
only a finish-only path may run, and only after actual directly owned child reap;
it rechecks marker/lease and captures source identities before publication or
cold cleanup. The INTERRUPTED verdict and actual signal wait status remain.
No suite command resumes after cancellation. Unreaped children, output-collection
failure, lease/marker loss or failed publication keep the target and cannot
qualify. This narrows the native repair amendment's conservative all-interrupt
retention to the accepted D44/D45 finished-use rule. Tracked source deletions
are captured through Git's explicit deleted inventory and invalidate older sets;
a disappearing untracked source still fails capture.

Contention sampling occurs at start/end and every 15 seconds while the command
runner is driven. Probes own/reap their direct children, inherit the same marker
open description, and never acquire signalling authority from process metadata.
The sampler excludes the gate's process-parent closure, records maximum load,
and preserves unavailable query data. macOS reads the unprivileged thermal
pressure notification state; Linux discloses the unsupported portable query.
These observations establish no idle threshold or timing acceptance by themselves.
Probe statuses are retained separately from primary step indices; an unreaped
probe poisons the whole use, including handled-interrupt finish, and keeps the
target. Optional query failure is measurement data only after real probe reap.
The public judge content identity is preserved by export redaction; secret tokens,
session values and unknown gate-control values remain redacted.

D45 remains owner-accepted interim checked-path/by-name mutation risk, to revisit
when storage changes; it is not resolved. FS1 escaped descendants and manual
cargo-clean/marker removal remain separate residuals. Existing-marker production recovery uses the owner-authorized free same-inode
marker policy above; RC18 is replaced as a precondition, not universally proved. Historical launch findings remain owner-set-aside preconditions.
The unchanged seven C files are independent reproducers; fixture/contract
mismatches must be named for their owner, never silently edited here. Whole-gate
reviews, final-head Linux, Mac/Linux timings, R4/R11 names/counts and nextest's

## Goal

A builder gets a verdict on a change in minutes (`fast`), a pull request is gated by one full suite run (`pr`), and a goal or release is gated by one cold, folded run (`full`), with every protection of today's gate still in force and shown to fail when it should.

Those of the spec. In addition: no change to what a tier's static steps check (`fmt`, `clippy`, `crate-graph`, `cargo-deny` keep their commands); no general test-runner abstraction beyond the two runners named here; no link checker or other new documentation check.

### 3. The folded suite run (D7–D13)

Per run the gate creates one disposable root under the temporary directory, with a sentinel `home/`, an empty `cwd/` outside the workspace, `shims/` and `witness/`. It is removed at the end; on failure the listing of what appeared in `home/` and the shim log are copied to the run directory first.

Environment of the suite process: started from the gate's own environment, then `HOME` = sentinel, `PATH` = shims first, `CARGO_HOME` and `RUSTUP_HOME` explicit (default: under the real home, captured before anything moves), `RUSTUP_TOOLCHAIN` = the channel in `rust-toolchain.toml`, `CARGO_TARGET_DIR` = the tier's target, the witness variable set, and the removals of D8 as amended by D26. The names removed are printed; values are not.

Inherited variables (D26) are checked in the preflight, before the lease is taken and before any step runs. The session list is one constant in `hermetic.rs`; the `[env]` keys are read from `.cargo/config.toml`. Any other `ORCH_*` or `ORCHESTRY_*` name refuses the run and is listed. The refusal message names the way out: unset the variable, or run the opt-in test directly with cargo.

Shims: one constant list (`claude`, `codex`, `cursor`, `cursor-agent`, `agent`, `opencode`, `pi`, `grok`, `agy`). Each shim appends its name and arguments (truncated) to a log outside the sentinel and exits 127. A test ties the list to the adapters' default binary names, so an adapter cannot be added without a shim (should).

The run itself, sequential runner (PR 1). Both commands run from the outside `cwd/` and name the workspace with `--manifest-path`:

1. `cargo test --workspace --no-run --message-format=json` in that environment. This compiles and yields the map from each test executable to its package, target and kind.
2. `cargo test --workspace --no-fail-fast` in the same environment. Output and status are kept.
3. The inventory parser reads the log and the map. It produces one row per test (`kind`, `package`, `target`, `test`, `status`; an ignored test is a row with status `ignored`, so platform differences show by name) and checks D9: no failure, at least one test executed, every executable of the map present with a completed result line, counts equal to the result lines, status and inventory in agreement. Text inside a `failures:` section is not parsed as results.
4. The witness record is checked against the environment (D10).

`home-hygiene` then lists the sentinel (anything but `.cargo` and `.rustup` fails), `no-real-cli` reads the shim log, and both report “not evaluated” as a failure when the witness is absent (D11). Neither sees a child that a test starts with a cleared environment and a `PATH` or `HOME` of its own (D29).

The parser reads one original log. Unsupported child-output framing or unreconciled counts fail as “inconsistent inventory”; the ordinary-framing amendment above defines the two additionally supported bounded frames. False failures are diagnosed, never rerun away.

For a selected run (`fast`), the witness target is run first by itself in the same environment, because a package selection may not include `xtask`.

With nextest (PR 4) only steps 1–3 change: the expected set comes from `cargo nextest list`, the executed set from its JUnit report, they must be equal, and the gate passes `--retries 0` and `--no-tests fail` explicitly, so the design does not rest on nextest's defaults. Unverified until the pilot: that nextest reads cargo's `[env]` only from the working directory. The witness detects the opposite on every run.

`real-home` (D13, D28): the snapshot covers `~/.orchestry` to depth 4 and at most 5,000 entries. It walks level by level, each directory in name order, and records a symbolic link as an entry without following it. A complete comparison with no difference reads `unchanged (N entries)`. One cut short by a bound reads `no difference in N entries compared; partial: <bound reached>` and sets `real-home-coverage: partial` in the result. The two bounds are constants; changing them is a design change.

### 4. Targets and stale artifacts (D14–D16)

| Tier | `CARGO_TARGET_DIR` | Prepared how |
|---|---|---|
| `full` | `target/gate` | deleted, then built; deleted at exit unless `--keep`; refuses under 12 GB free. Each deletion needs established cessation of the writers of an earlier gate use (D32, D36); without it the target is left and the run says so. A `target/gate` that exists at the start is deleted only on the affirmative provenance of D33; without it the run is refused, which is every such start until P5 exists (sixth amendment). Eighth amendment (D41, D44–D46): the condition on each deletion is now that the use is finished (D42), or, for a target left by an earlier use, that the run holds the lease and the lock of the use marker. A `target/gate` that exists at the start is deleted on that condition, whatever its history; it is not refused for want of provenance. Ninth amendment (D42, D45): a run started without the configured lease is refused before it deletes anything, and the structural check covers the state files as well |
| `pr`, `fast` | `target/gate-warm` | checked against its record; reset when untrusted. A reset or a reuse needs established cessation of the previous use's writers (D32); without it the run refuses. A target has unknown history, and is refused as well, when the provenance that its lifecycle state requires is missing, unreadable, corrupt, incomplete or unresolved (D33, sixth amendment). Seventh amendment: the marker and the completed record are a lifecycle trace. In a completed state D35 has removed the marker on purpose, so that absence is not missing provenance and the two files are not required at once; a use without a completed record is unfinished, not never-used. Neither file by itself proves cessation or authorizes a reset or a reuse, and relying on the trace waits for P5's review and P1's observation (section 12). Eighth amendment (D41–D46): a reuse needs no marker and a complete record that matches (D43); everything else is a reset, including a missing or damaged record, and a reset needs the lease, the lock of the use marker and the structural check of D45, not an observation of every writer. The refusals that remain are a marker whose lock is not granted and a failed structural check. Ninth amendment (D42, D43): a complete record is one that cannot be a truncated one and that covers the exact set of source files. A run started without the configured lease is refused. Where the recovery after the death of a holder has not been shown, a marker found at admission is refused whether or not its lock is granted |
| `full --warm` | the developer's target | untouched; result marked “not a gate” |
| building `xtask` itself | `target/gate-xtask` | by `gate.sh`: deleted when the judge identity differs from its stamp (D27) |

The warm record holds the canonical worktree root, the toolchain identity, the end time of the last build and, for every tracked and untracked source file, a content identity. `target/gate-warm` must be a real directory inside the worktree; a symbolic link is refused. The record is written around a build (D30 as amended by D35). The marker and the identities are written before the first building command. The record is written, and the marker removed, only when the cessation of every writer of this use has been independently established (D32, D33). That is the condition after a successful build, after a failed compilation and after an interrupt the gate handled alike; the return of the last building command, the exit of the gate's direct children, end of file on a channel or the end of a bounded wait is not that condition. The end time in the record is taken when cessation is established. Where it is not established, no record is written and the marker stays (D34). Eighth amendment (D42, D44): “the cessation of every writer has been independently established” is replaced by “the use is finished”: the holder has reaped every process it started directly, holds the lease and holds the lock of its use marker. The exit of the gate's directly started processes is therefore the condition, together with the lease; end of file on a channel and the end of a bounded wait still are not. The marker is the use marker of D43, created and locked before the target is examined; the earlier record is removed before the first building command; the record is written by temporary file and rename, and the marker is removed after it. Ninth amendment (D43, D44): the holder never unlocks the marker's lock; it closes its descriptor. The marker and its directory are synchronized to stable storage before the target is changed, and the temporary file, the rename and the directory before the marker is removed. The source identities are captured before the first building command and again at the finish; if they differ, no record is published and the next run resets.

A run that finds a marker at its start does not reset the target by itself. It refuses, changes nothing and says why, unless the cessation of the earlier use's writers is independently established; only then does it reset, with `reset: previous build did not finish`. The same precondition applies to every other reset and to reuse. A missing recorded process id, the marker's state, an expired wait or an operator's acknowledgement does not meet it (D33, D34). There is no automatic recovery after a hard kill and none after a normal finish that left its writers unresolved; recovery stays refused until cessation is established. Sixth amendment (D35): this is the rule for every use that ended without established cessation, whether by a normal finish, a failed compilation, a handled interrupt or the death of the holder. No record was completed for it, so once its cessation is established the next run resets, and it never reports `reused`. A warm target that exists with neither marker nor record, or with either of them unreadable, corrupt or incomplete, has unknown history: that is not a reset with `no record` or `record unreadable` but a refusal, unless the provenance of D33 is affirmatively established (section 11). The earlier wording of this paragraph (a marker "resets the target"; the record written "after the last" command) is superseded with the clauses of D30 it restated. Eighth amendment (D42, D46): a run that finds a marker acquires its lock under the lease. While the lock is not granted it refuses and changes nothing, as this paragraph says, also after a wait, with a process id gone or on an acknowledgement. Once the lock is granted it resets, with `reset: previous build did not finish`: the kernel then shows that no process still holds the description that the earlier gate gave to the processes it started. A warm target with neither marker nor record, or with a record that is unreadable, corrupt or incomplete, is reset with `no record` or `record unreadable` and is not refused; it is never reused. The sentence above that there is no automatic recovery after a hard kill is superseded to that extent. Ninth amendment (D42, D43, D46): that reset is available only where the recovery has been shown for the platform, the kind of filesystem and the commands (RC18); elsewhere a marker found at admission is refused, whether or not its lock is granted. The refusal names the marker's path and says that `target/` must not be removed while a process that holds the marker is alive: after such a removal the next run cannot see that process and builds beside it (RC14).

A content identity is the git blob id of the file's content (`git hash-object`, paths passed on standard input, never through a shell). For a clean tree it equals the id in the commit's tree, which is what lets `gate evidence verify` recompute an identity from a commit.

The bootstrap in `gate.sh` (D27), in order: change to the repository root; compute the judge identity as the blob id of the sorted list of `<blob id> <path>` lines for the files of D27; if `target/gate-xtask/judge-id` is missing or differs, delete `target/gate-xtask`; remove the stamp; `cargo build -p xtask` with `CARGO_TARGET_DIR=target/gate-xtask` (an inherited value is ignored); write the stamp; start `target/gate-xtask/debug/xtask gate` with the caller's arguments and `XTASK_GATE_JUDGE_ID` set. This is all the shell does. `cargo xtask gate …` still works for the helper subcommands and for development; a tier started that way has no judge identity and cannot qualify.

### 5. Selection (D19–D20)

`gate select` reads the changes with `git diff --name-status -z -M` against the merge base, plus `git ls-files --others --exclude-standard -z`, and the graph with `cargo metadata --no-deps --format-version 1`. All subprocesses take arguments as a list. The two `--…-from` options replace both sources with files, which is how the table test runs without git or cargo.

Output (`--format json`): `schema`, `mode` (`docs-only`, `packages` or `all`), `packages` (sorted), `base`, and `reasons`, one per path: `path`, `class` (`doc`, `crate`, `global`, `coupled`, `unknown`, `error`), `selects`, `why`. `--format github` writes `mode` and `packages` as job outputs. The command exits 0 for every classification, including errors (which select everything); only a usage error exits 2.

`fast` names every selected package with `-p`; mode `all` runs the workspace. A binary that a selected test starts by path must be built from the same tree before that test starts, and the gate sets that order itself (D40): it first completes a build that brings the binary up to date in the tier's target, and starts a test process only after that build succeeded. The order is not inferred from how cargo schedules one invocation, and a binary already present in a warm target is not trusted. This holds for every tier that runs such a test, the workspace runs of `pr` and `full` included. Section 3's two commands (`--no-run`, then the run) are an order the gate sets; that the first of them builds the `orch` binary for a `-p` selection is an assumption until the two-marker probe of section 12 shows it. If it does not, task I adds an explicit build of the binary before the tests. The exact commands are the implementation's.

The coupling table is maintained by hand and has two rows today. A document row: `docs/ARCHITECTURE.md` selects `xtask`. A package row (D39, F16): after the normal reverse-dependency closure, a selection that contains `orch-cli` and not `orch-infra` also selects `orch-infra`. The row therefore fires for a change in `orch-cli` and for a change in any crate that `orch-cli` depends on and `orch-infra` does not. A package row adds the coupled package only, not that package's dependents, and adds its own reason with class `coupled`, so a path can have more than one reason. A change in `orch-infra` itself selects it and its dependents through the normal closure, with no `coupled` reason. The table is the known gap of selection: a document that a test reads, or a binary that another package's test starts, that is not in the table is caught by `pr`, not by `fast`.

The selector frozen at G fires the package row only for a change in `orch-cli` itself, which is the superseded trigger of D31. Changing it to the trigger above, the added TV38 case and the build-order evidence are PR 2 work (section 12); the frozen G and H are not edited by this plan.

### 6. Lease and contention (D21–D22)

Lock file: `/tmp/r-orch-gate.lease`, created with mode 0600 and never through a symbolic link. A file owned by another account is refused with a message. A second file is the turnstile that keeps an exclusive waiter from starving. `XTASK_GATE_LEASE_DIR` moves both files; the gate's own tests always set it, so a nested gate inside the suite never touches the host lease. A run that used it cannot qualify.

`gate lease exec` holds the exclusive lease around any command, for timing series and qualification. It passes a token to its children; a gate that finds its token in the holder record proceeds and records `lease: inherited`. Obligation RS7 (section 12) limits this: the holder record is a diagnostic, so the token counts only while the exclusive lock is still held by a live holder; if a non-blocking lock attempt succeeds, the holder is gone and the gate must take the lease normally.

Contention is sampled every 15 seconds: the one-minute load average (`/proc/loadavg` on Linux, `sysctl -n vm.loadavg` on macOS) and the count of `cargo`, `rustc`, `rustdoc`, `clippy-driver` and `cargo-nextest` processes that do not descend from the gate (`ps -axo pid=,ppid=,comm=`). The result records the maxima and `foreign-build-activity: yes|no|unavailable`. The load threshold that makes a timing sample “idle” is the performance engineer's, declared before measuring.

The holder of the lease is the process the caller started, which may have replaced itself by `exec`; it alone owns the lock's file descriptor, no descendant inherits it and no helper keeps it after the holder is killed (D37; section 12, K-5). Eighth amendment (D43): the lock of the use marker is a different descriptor. The holder hands an open description of it to every process it starts directly, on purpose; the lease's descriptor is still handed to none. Ninth amendment (D42, D43): that description bears on safety, because a later run is admitted only when no process holds it. The holder never unlocks it and ends its own hold only by closing. The target lifecycle needs the configured lease: a run started with `--no-lease` is refused before it creates a marker or changes a target, and a run that inherited the lease checks the inherited holder again at its finish (RS7).

On interrupt the gate stops its own children, releases the lease and writes `INTERRUPTED`. Obligation INV-T (section 12) bounds every wait the gate performs, including this one; the bound has no number yet (D38). It removes the cold target only when the cessation of the target's writers has been independently established (D32, D36). Otherwise it leaves `target/gate` in place, writes no warm record, lists what survived or could not be attributed, and says that the target was kept and why: the result carries `target: kept (<reason>)` and `qualifying: no` with that reason (D34, section 11). A handled signal, the exit of the direct children and the end of the bounded wait do not authorize the removal. Eighth amendment (D45, D46): the gate stops the processes it started directly, through its own handles or through a process group it created for one of them while that process is unreaped, and signals nothing else. When each of them has been reaped within the bound, the use is finished: the cold target is removed and the warm record is published. When one has not exited at the end of the bound, the target is left, the marker stays and the result says `target: kept (<reason>)`. A descendant that the gate did not start itself is neither awaited nor reported; that is the risk the owner accepted (D41). Ninth amendment (D45): a process group is signalled only while its leader, the directly started process, has not been reaped. An escalation to the group therefore comes before the leader is reaped, and the reaping ends that authority.

### 7. Evidence, CI and the rules change (D17, D23; R14, R15)

A qualifying `<linux-host>` run is `./xtask/gate.sh pr --evidence <dir> --host-label <label>` in a clean dedicated checkout of the exact final PR head. The evidence directory holds the result (with `judge-source-id` and `real-home-coverage`), every step log, the inventory, the lock-file digest, the tool versions, the names of the environment variables that were set or removed, and a digest manifest. The pull request links a durable copy and states the manifest's digest. Before the owner merges, a reviewer runs `gate evidence verify <dir> --commit <PR head>` in a clone that has that commit, and compares the inventory with the previous accepted one by name. The command also recomputes the judge identity from the commit and rejects evidence whose `judge-source-id` is absent or different (D27). A moved or dirty tree, a missing tool, log or inventory, an unexplained failure or a lost lease cannot qualify. A run that kept its target because the cessation of its writers was unresolved cannot qualify either, in any tier (D34). Eighth amendment: since D41 that is a run whose own use was not finished when it ended (D46). Ninth amendment: that includes a run in which an operation on the target or on its state failed after the target was changed, and a run whose inherited lease holder was gone at the finish (D44, D46). Secrets are not copied.

GitHub's PR CI keeps running: tier `pr` once for code, the documentation checks only for a documentation-only change. When qualifying `<linux-host>` evidence exists the GitHub suite result is supplemental; when `<linux-host>` is offline, busy or cannot be verified, the one green GitHub run at the final head is the evidence, and nobody waits for the worker. If the Mac is unavailable, the report says “macOS not run, Mac unavailable”. A failure anywhere is kept and diagnosed; a green run on another platform does not erase it. Pushes to `main` keep the complete run. Measurements on real Linux CI remain acceptance evidence.

CI shape (PR 3): job `changes` runs `gate select --format github`; on a push to `main` the mode is forced to `all`, and the weekly schedule runs `check` alone as today. `check` has `if: always()`, fails first if `changes` did not succeed, then runs either the documentation checks or today's static commands (the pinned `cargo-deny` action stays). `test` is skipped by its job condition in documentation-only mode and otherwise runs `./xtask/gate.sh pr --part suite --no-lease "github-hosted runner"`. The checkout fetches enough history for the merge base; a missing base selects everything. Permissions stay read-only and credentials are not persisted. The test in `xtask/src/linux.rs` that mirrors `ci.yml` changes in the same pull request. Ninth amendment (D42): as proposed, the target lifecycle refuses a run that was started with `--no-lease`, so this CI command cannot use a gate target as it is written here. How the hosted job obtains one is an open obligation of PR 3 (open item 19). The approved CI direction is not withdrawn, and this plan does not resolve the conflict.

Job `ambient` (D25): runs only on a push to `main`; same setup steps as today's `test` job (toolchain, cache, tmux); then `cargo test --workspace --no-fail-fast` from the repository root, with no gate wrapper. It is never named `check` or `test` and is not added to any rule. Which directories the cache action saves once `target/gate-warm` and `target/gate-xtask` exist, and what that costs in cache size and save time, is decided and measured in PR 3.

Rules change. The ruleset is shared by `main` and `release/**`, so removing `test` from it would also drop it from `release/**`. The change is therefore a split: one rule set for `main` requiring `check`, one for `release/**` requiring `check` and `test`, everything else identical, or an equivalent reviewed configuration. The exact configuration and its rollback (the saved current ruleset) are prepared for review with PR 3. The owner applies it; the lead reads the live rules back (TV54). No agent changes a rule, merges as administrator or reports a synthetic status. Price, accepted by the owner: GitHub no longer blocks a merge to `main` on a failing suite; the owner and the reviewer check the linked evidence before every merge.

How the gate tests stay cheap and hermetic: each case builds a miniature workspace in a temporary directory (one crate with no dependencies, a copy of the toolchain pin, the witness test) and runs the real `xtask` binary with that directory as the working directory, `--part suite`, a temporary directory as its `HOME` (the “real home” of that run), explicit `CARGO_HOME` and `RUSTUP_HOME`, and its own `XTASK_GATE_LEASE_DIR`. No case touches the developer's home, the host lease or a real agent CLI, also when the suite itself runs under an outer gate. The inventory and selection cases use files only; the evidence-verification cases use files and a temporary git repository; none of them starts cargo. The bootstrap case (TV19) copies `gate.sh` into a miniature workspace whose `xtask` package is a stand-in that prints a constant from its source and the judge identity it was given. Budget: the new test files together stay under 90 seconds on the Mac; the measured figure goes in the PR 1 report.

A complete `full` or `pr` with every step passing cannot be produced on a miniature workspace (`crate-graph` needs the real one). That wording is covered by the real runs of PR 1.

### 10. Alternatives rejected

A1–A10 and A19–A22 are in the ADR. Design-level ones:

- A11. Include the selector's source in the test crate with `#[path]`. Changes how nested modules resolve and compiles the code twice under different lint exposure.
- A12. Give `xtask` a library target so tests can call functions. Adds a second registry file that every builder would touch.
- A13. Parse only the `test result:` lines, as today. Cannot name tests or notice a binary that never reported.
- A14. Skip a second `cargo test --no-run` pass and take executables from the `Running` lines. Two packages with the same test file name would collide.
- A15. Compare the real home by content hash. Reads files the gate has no reason to read.
- A16. Extend `real-home` to agent CLI directories. They change constantly on a host that runs agents; the step would always fail.
- A17. Use the lease for ordinary `cargo` commands through a wrapper. Not enforceable, and the owner chose measured and gating runs only.
- A18. Run static steps in parallel with the suite. Saves time and contaminates every timing.

### 11. The interface the builders share

The tests are written before the implementation and by other people, so the names below are fixed here. Anything not listed is the implementer's choice, and a test must not assert it.

Variables the gate defines:

| Variable | Set by | Meaning |
|---|---|---|
| `XTASK_GATE_WITNESS_DIR` | the gate, for the suite | the witness test writes `witness.txt` there; unset, it does nothing and passes |
| `XTASK_GATE_JUDGE_ID` | `gate.sh` | the judge identity (D27) |
| `XTASK_GATE_LEASE_DIR` | tests | directory of the lease files; a run that used it cannot qualify |
| `XTASK_GATE_LEASE_TOKEN` | `gate lease exec`, for its children | the holder's token |

`witness.txt` is lines of `key=value`: `schema=1`, `home=<HOME as the test sees it>`, `global_config_redirect=set|unset`, `path_first=<first PATH entry>`, and one `orch_var=<NAME>` per `ORCH_*` or `ORCHESTRY_*` variable present. The witness test uses `std` only, so the gate tests plant the same source file in a miniature workspace.

Lease files, in `/tmp` or in `XTASK_GATE_LEASE_DIR`: `r-orch-gate.lease` (the lock), `r-orch-gate.turnstile`, `r-orch-gate.holder` (diagnostic record).

`target/gate-result.txt` keeps its existing lines (`verdict:`, `commit:`, `tree:`, `dirty:`, `moved:`, `mode:`, `started:`, `finished:`, then the table). The value of `verdict:` starts with one of `IN PROGRESS`, `PASSED`, `FAILED`, `ENV-LIMITED`, `REFUSED`, `INTERRUPTED`; a complete tier appends ` (tier <name>)`, a partial run appends ` (part <name>)`. Added lines:

| Line | Values |
|---|---|
| `tier:` | `fast`, `pr`, `full` |
| `part:` | `suite`, `static`, or `-` for a complete tier |
| `run-dir:` | path of this run's directory under `target/gate-runs/` |
| `target:` | `cold`, `reused`, `reset: <reason>`, `kept (<reason>)`, or `developer (not a gate)` |
| `lease:` | `exclusive`, `shared`, `inherited`, `none: <reason>`, `lost` |
| `foreign-build-activity:` | `yes`, `no`, `unavailable` |
| `real-home-coverage:` | `complete`, `partial`, or `-` when the step did not run |
| `judge-source-id:` | the identity, or `absent` |
| `qualifying:` | `yes`, or `no: <reasons>` |

Reset reasons: `no record`, `record unreadable`, `another worktree`, `toolchain changed`, `content changed without a newer modification time`, `previous build did not finish`. A reason says why a reset is due. The reset is carried out, and the reason reported, only when the cessation of the previous use's writers is established (D32); otherwise the run is refused. Whether an existing target has a previous use is decided by affirmative provenance, not by the absence of a known gate use (D33; sixth amendment, which withdraws the earlier wording "whose content no gate use is known to have produced"). A target that is affirmatively established never to have been used by a gate, and that holds a closed controlled plant (TV13), has no previous use: D14 and D15 apply to it as before, and `reset: no record` is reported as before. A target whose last gate use is closed by established cessation is a separate case, under D32; no marker, token or record establishes that cessation by itself. A target that exists and whose history is missing, unreadable, corrupt, incomplete or otherwise unresolved is refused, warm or cold: `no record` and `record unreadable` say why a reset would be due and are not provenance. The absence of a marker, a directory that was absent or recreated, the cooperative lease, a missing process id and an operator's acknowledgement establish no provenance. Until the durable provenance of P5 exists and is reviewed, never-used status cannot be established, so a `target/gate` that exists at the start of `full` is refused and TV13's deletion is unmet (section 12). A target that does not exist is created and reported as before; its absence is not provenance. `previous build did not finish` is therefore reported only after that cessation was established, never for a marker alone (D35). The wording of the refusal for unresolved writers is not fixed here; the frozen C tests match `warm target in use`, a reason and the writer's process id for the cases they have (section 12, RS1 and RS2), and any further fixed substring is added with C's next owned edit. Eighth amendment (D43, D45, D46): a reason is reported, and the reset carried out, when the run holds the lease and the lock of the use marker and the structural check passes. A target whose history is missing, unreadable, corrupt or incomplete is reset with `no record` or `record unreadable`; it is not refused, and it is never reused. A `target/gate` that exists at the start of `full` is deleted. `previous build did not finish` is reported when a marker was found and its lock was granted. The refusals that remain are a marker whose lock is not granted (the frozen C tests match `warm target in use` for it) and a failed structural check. The process ids that such a refusal prints come from the marker and are a diagnostic only. Ninth amendment (D42, D45, D46): three more refusals remain: a run started without the configured lease; a marker where the recovery after the death of a holder is not shown; and a state file that is not a regular file of the gate's account. The refusal for a marker names its absolute path, gives the marker's diagnostics as not validated or as `unavailable`, says that the target is in use or that an earlier use did not finish, gives a read-only hint for finding the processes that hold the file, and says not to remove `target/` while one of them is alive. The fixed strings are P7's.

Kept target (sixth amendment; D34). A run that ends with the cessation of its writers unresolved writes `target: kept (<reason>)` and `qualifying: no: <reasons>`, where the reasons include the unresolved cessation. Both are shown in the summary of every tier, `fast` included. Step verdicts that were observed may stand in the table; they never make the run qualifying. A later run that is refused because of that earlier use names the earlier run's identity and end time where validated diagnostics supply them, and says `unavailable` where they do not; it invents no identity, takes no marker as authority and does not count the disclosure as cessation. The value of `verdict:` and the exit status of a run that kept its target, the fixed text of `<reason>`, and whether the start-of-run value of `target:` is shown beside `kept` are not fixed here: they are task F's interface obligation, reviewed before C asserts them. Eighth amendment (D46): a target is kept when the run's own use was not finished: a directly started process had not exited when the teardown bound ended, the lease was lost, or the marker's path no longer named the file the holder had locked. A normal finish and a failed compilation with every directly started process reaped do not keep the target. Ninth amendment (D44, D46): a target is also kept, and the run does not qualify, when an operation on the target or on its state failed after the target was changed, or when the holder of an inherited lease was gone at the finish.

Step details that tests match by substring: `no test executed`, `not evaluated`, `inconsistent inventory`, `incomplete inventory`, `witness missing`, `witness mismatch`, `not available yet`, `not a gate`, `unchanged`, `partial`, `created`. A refusal prints `REFUSED:` and its reason; for D26 the reason starts with `inherited variable` and lists the names.

Inventory file: one line per test, tab-separated `kind`, `package`, `target`, `test`, `status`, sorted bytewise. `kind` is cargo's target kind (`lib`, `bin`, `test`, `example`, `bench`) or `doc`. `status` is `ok`, `failed` or `ignored`. For `gate inventory`, `--executables` takes the JSON lines that `cargo test --no-run --message-format=json` prints; the command exits 0 when the log is accepted and 1 with the reason otherwise.

Evidence directory: `result.txt`, `steps/` (one log per step), `inventory.tsv`, `environment.txt` (names only), `tools.txt`, and `MANIFEST`, which lists `<blob id>  <path>` for every other file, sorted by path. The digest a pull request states is the blob id of `MANIFEST`. Blob ids detect a file changed after the fact; like the rest of the evidence they do not resist a producer who rewrites it (ADR, Consequences).

Selection output is the JSON of section 5 with `schema` 1.

**C resources and helper exits.** The miniature tests of task C discover the already installed pinned toolchain and the native `rustup` from the invoking Cargo, tool-home and `PATH` locations, then provision private, credential-free Cargo and Rustup homes and proxy-first tool `PATH`s for their children. A missing exported `CARGO_HOME` or `RUSTUP_HOME` is resolved from the invoking tool location or the pre-sentinel `HOME` convention; an explicit resource override is authoritative and is never replaced by a fallback. No `GATE_CONTRACT_RESOURCES` variable is required, and the gate neither sets nor advertises one. The tests do not install anything, copy host configuration or credentials, extend the evidence allowlist, or bypass the empty-`RUSTUP_HOME` test (TV6) by calling the toolchain directly. A failure to discover or provision resources is reported as a failure, never skipped. Task C owns the fixture implementation and the default-workflow and TV6 tests; task F owns the propagation of D8. The seven names that `environment.txt` may record as set stay `HOME`, `PATH`, `CARGO_HOME`, `RUSTUP_HOME`, `RUSTUP_TOOLCHAIN`, `CARGO_TARGET_DIR` and `XTASK_GATE_WITNESS_DIR`; controls that a test applies to its own private children are not part of that record.

`gate evidence verify` exits 0 when it accepts the evidence, 1 with the reason when it rejects the evidence or the expected-commit inputs (corrupt, incomplete, unreadable or nonqualifying), and 2 on a command-line usage error. A nonqualifying export is a rejection (1) for the verifier; exit 3 belongs to a producer run or export that succeeded but does not qualify. Verification takes no lease and runs no tier. A diagnostic names the rejected file, field, step or predicate: a mutated step status names that step and `status`, a mutated step exit names that step and `exit`, and a moved head may be named `head-end` or `moved`. No other exact wording is fixed. This clarifies a point the earlier text left open (this section states exits only for `gate inventory`). F0's exit 2 `not available yet` is dispatch evidence at the seam, not the rejection oracle.

*K-5, the holder of the lease.* The holder of the gate lease is the process the caller starts, which may have been replaced by `exec`, and it is the sole owner of the lease's file descriptor. *Cold-target removal under unresolved writers (TV64).* The removal of the cold target `target/gate` after a handled interrupt is a mutation of the target, like a warm reset, reuse or publication, and it falls under K-1 to K-4 in the same way. *Why recovery stays refused.* A wait can show that time passed and that the processes the gate could see are gone. A descendant that was re-parented is not among them, so the end of the wait leaves the question open, and an open question is treated as a live writer (D34). If the gate reset or reused the target then, a late write would land in a tree that the next record describes as clean. The outcome of an exhausted wait is therefore the refusal, and it is still the refusal on the next run and the one after: elapsed time, a process id that is gone, the state of the marker and a person's acknowledgement add no observation of the writers. The same reasoning holds at a normal finish. A passing suite says that the tests passed. It does not say that every process a test or a build script started has exited. So the gate publishes no record and removes no cold target at a normal finish either, unless cessation is established. This does not say that every run under a shared account leaves writers behind, and it does not ask the gate to certify other work of the account. It says that the gate may not assume that its own descendants are gone.

*The mechanism, in one paragraph.* The lifecycle needs the configured cooperative lease; a run started without it is refused before it creates or changes anything (D42). For each target the gate keeps a use marker and, for the warm target, a completed record, in a gate-owned directory inside `target/` and outside both targets (D43). The marker exists while a use is unfinished and carries a kernel lock that belongs to the open file description. The holder takes that lock before it touches the target, checks that the marker's path still names the file it locked, and hands an open description of the lock to every process it starts directly. It never unlocks the lock; it only closes its own descriptor. A use is finished when the holder has reaped those processes and still holds the lease and the lock (D42); then, if the source did not change during the build, it publishes the record and removes the marker (D44). If the holder dies, the marker stays and its lock stays held for as long as a process holds the description: a command the holder started directly, or a descendant that inherited it. The next run, under the lease, tries that lock: not granted means refused and nothing changed; granted means reset, where that recovery has been shown (RC18). No process id, no listing of processes, no elapsed time and no lease by itself stands in for that lock.

*State table.* What a run does at admission, after it has the lease in its tier's mode (without it: the lease's own wait and exit 75, D21). A run started with `--no-lease` is refused before admission, and no row applies to it (D42). “Lock” is the lock of the use marker. The structural check of D45 comes first in every row; if it fails, the run is `REFUSED` with exit 1 and nothing is deleted (RC17). It covers the state files as well as the directories. After the lock is granted the holder checks that the marker's path still names the locked file, and refuses if it does not (RC19).

*Endings.* D46 has the table. In short: a normal finish and a failed compilation finish the use when every directly started process is reaped; the exit status gives the verdict and not the finish. A handled INT, TERM or HUP finishes the use if those processes exit within the bound, and otherwise keeps the target. The death of the holder, by SIGKILL or by any signal it does not handle, finishes nothing: the marker stays and the next run is S6, S7 or S9. What survives the death of the holder is the marker, its lock in the hands of the processes still running, and the target as it was; the kernel has freed the lease, and no helper holds it (D37). What is no longer proved, at any ending, is that a descendant the gate did not start has stopped. Three more endings keep the target and do not qualify: the lease was lost, or the holder of an inherited lease was gone at the finish; an operation on the target or on its state failed after the target was changed; and the marker's path no longer named the locked file. A source file that changed between the capture before the first building command and the capture at the finish does not keep the target: the use is finished, no record is published, and the next run resets.

*Limits that stay, and what is unverified.* The gate and its operator share one account: a marker or a record changed by hand, and a `target/` removed while a use is running, are not detected. In particular, a `target/` removed while a command of a killed gate is still running leaves the next run with no marker to refuse on, and it builds beside that command (RC14). That is disclosed and steered against, not prevented. The lease is cooperative: a plain `cargo` command in a gate-owned target is not excluded. Unverified, and to be shown by RC18 before recovery after the death of the holder is relied on: that the real `cargo` on macOS and on Linux keeps an inherited descriptor until it exits; that the standard library's file lock on the pinned toolchain is held by the open description on both platforms, so that it survives the holder in a process that inherited it; that the lock is released only by an explicit unlock or by the last close of the description; that the filesystem under the worktree gives a lock of that kind and not a per-process one; and which calls synchronize a file and a directory to stable storage on each platform without a new dependency. A known route that needs no dependency and no `unsafe` is to give the lock's description to a command as a standard stream it does not use; whether F takes it is F's choice. It is unverified in this project. If F takes it, the suite's commands see a different standard stream than in an ordinary run; that is disclosed in the evidence, and the comparison of R4 and R11 uses the same stream on both sides or diagnoses the difference.

## Test plan

Observer HOME repair (2026-11-15): first add a startup HOME record and assertion
to the existing native Python probe and show that it rejects the original Rust

observer home before exec; retain ordinary Python cache behavior and all native

the corrected folded measurement; no broad workspace measurement belongs here.

The spec's acceptance checks; the vectors above; the CI set on every pull request. `./xtask/gate.sh full` on macOS and on native Linux for PR 1 and at the end, because the work changes process handling and the gate itself. PR 1 also runs the gate of the base commit once at the same tree, for the comparison of R4. Both runs of that comparison hold the exclusive lease on an otherwise idle host. One run on each side cannot tell a failure caused by the fold from an intermittent one, so every test whose result differs is then run by itself in both environments. The report lists every difference with what those runs showed, including the ones that did not repeat; an intermittent one is triaged under R7. None of this is a rerun to obtain a pass. Timing and qualification runs hold the exclusive lease on an otherwise idle host. Reviewers use bounded disposable probes; no probe uses a real home or a real agent CLI. No user interface changes, so no tmux end-to-end test is added.

Reviews: each pull request gets independent code, security and resilience reviews of what it touches, at a frozen commit. Security covers subprocesses, paths, the untrusted diff and CI; resilience covers failure, interruption, cleanup, the lease, kept diagnostics and rollback. A fact check covers timings, inventories and public claims. One red-team pass challenges the fold (task E). A blocking finding is fixed and reviewed again or goes to the owner; it is not overruled.

Price, from the approved plan: at least 40 nextest qualification runs (20 per platform), plus baselines, pilots, the fold comparison, the negative cases, CI validation and the final gates. At an illustrative 10 minutes each, qualification alone is 400 machine-minutes; that is arithmetic, not a measurement.
