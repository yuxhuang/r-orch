## Design and amendment

Implement approved node J in `.github/workflows/ci.yml`, `xtask/src/linux.rs` and `xtask/tests/ci_workflow.rs`. This supplements section 7 of the [goal plan](2026-11-14-tiered-checks.md); the goal stays incomplete. Remove the proposed CI `--no-lease` invocation: it is refused by the current lifecycle. Use `./xtask/gate.sh pr --part suite --receipt <new-dir> --lease-wait 5 --host-label github-hosted-linux` on the isolated hosted runner, with the normal default configured exclusive lease. Bootstrap and runtime share the supported admission mechanism. Do not remove target markers, reset manually, or bypass lifecycle checks.

`changes` runs on PR/main, with full history and a quoted explicit PR base; main publishes `all` regardless of selection. Missing/unresolvable base is conservative all. `check` depends on changes and has `always()`, explicitly exempting schedule from classification and failing on every other unsuccessful required classifier or invalid mode. Docs-only adds a workspace build to fmt/clippy/crate graph and the pinned deny action. `test` runs once for packages/all, skips docs-only/schedule. `ambient` runs `cargo test --workspace --no-fail-fast` only for main push, outside the wrapper. No path filters skip the workflow.

Keep the optional Docker Linux runner's ordinary checks and exact probed emulator skips: it cannot claim folded-hosted equivalence. Retain its original forward CI-to-Docker single-line run scan and minimum count of four alongside the reverse command, lock and probe assertions and the deliberate platform difference. A new CI-only-command mutant must fail the forward assertion. Focused workflow tests must check event/mode truth table, failed/cancelled/missing classification, unknown mode, main forcing all, supported lease options, ambient exclusion, pins/permissions and cache targets without introducing a YAML dependency. Do not build a new general YAML parser.

Caches use the pinned rust-cache action with `cache-targets: false` and `cache-bin: false`, no extra directories: only Cargo registry/git dependency caches. This excludes every target, including `gate-warm`, lifecycle markers/state, `gate-runs`, raw/exported receipts and cold gate targets. Hosted boots invalidate warm target records; never weaken boot checks. Separate local job targets remain uncached. Actual cache hit/key/size/save/restore durations remain unmeasured; no warm speed claim.

Keep the existing explicit 30-minute suite-job timeout provisionally; new-job headroom is unmeasured. The at-most-20-minute PR target stands. TV51/53 record actual durations; timeout is failure with incomplete diagnostics, never permission to retry. Preserve existing capture/teardown bounds.

Rejected: `--no-lease` (current lifecycle refusal); full PR execution in both jobs (duplicates the suite); ambient PR suite (duplicates the suite); whole-target cache (captures unrelated records); raw gate artifact upload (runbook privacy contract); treating a partial-export exit 3 as green (conflates nonqualification with success).
