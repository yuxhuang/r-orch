## Design and amendment

Implement approved node J in `.github/workflows/ci.yml`, `xtask/src/linux.rs` and `xtask/tests/ci_workflow.rs`. This supplements section 7 of the [goal plan](2026-11-14-tiered-checks.md); the goal stays incomplete. Remove the proposed CI `--no-lease` invocation: it is refused by the current lifecycle. Use `./xtask/gate.sh pr --part suite --lease-wait 5 --host-label github-hosted-linux` on the isolated hosted runner, with the normal default configured exclusive lease. Bootstrap and runtime share the supported admission mechanism. Do not remove target markers, reset manually, or bypass lifecycle checks.

`changes` runs on PR/main, with full history and a quoted explicit PR base; main publishes `all` regardless of selection. Missing/unresolvable base is conservative all. `check` depends on changes and has `always()`, explicitly exempting schedule from classification and failing on every other unsuccessful required classifier or invalid mode. Docs-only adds a workspace build to fmt/clippy/crate graph and the pinned deny action. `test` runs once for packages/all, skips docs-only/schedule. `ambient` runs `cargo test --workspace --no-fail-fast` only for main push, outside the wrapper. No path filters skip the workflow.

Keep the optional Docker Linux runner's ordinary checks and exact probed emulator skips: it cannot claim folded-hosted equivalence. Replace its old line-scanning CI mirror with assertions on relevant commands and on the deliberate platform difference. Focused workflow tests must check event/mode truth table, failed/cancelled/missing classification, unknown mode, main forcing all, supported lease options, ambient exclusion, pins/permissions and cache targets without introducing a YAML dependency. Do not build a new general YAML parser.

Intended caches: separate `target/ci-select`, `target/ci-check`, `target/gate-xtask`, `target/gate-warm`, and `target/ci-ambient`, each scoped to its job. Do not cache `target/gate-runs`, exports, holder records or cold `target/gate`. If the cache action cannot exclude lifecycle records safely, cache only dependency build subdirectories and keep all lifecycle state local to the runner. Record that the cache action prunes workspace artifacts; do not promise warm reuse or speed. Actual cache size, restore and save durations are unmeasured and require later CI logs.

Rejected: `--no-lease` (current lifecycle refusal); full PR execution in both jobs (duplicates the suite); ambient PR suite (duplicates the suite); whole-target cache (captures unrelated records); raw gate artifact upload (runbook privacy contract); treating a partial-export exit 3 as green (conflates nonqualification with success).

## Partial receipt interface hold

At base `3f92be07bc4847c95a85706dcb7ed9e1b64983df`, `GateCommand` exposes only select, inventory, evidence verify and lease helpers. There is no independent receipt-export command. `tier.rs` adds `partial run` and `checks incomplete or failed` qualification reasons for suite-only execution, then passes `args.evidence.is_some() && !qualifying` to `report::exit`; that returns 3 even if every executed suite step passed. `report::verify` requires qualification and all nine steps. `Run::finish` retains raw private records, and the runbook permits sharing only exporter-produced verified bundles.

Do not publish a workflow that either loses complete suite diagnostics or silently translates that refusal to green. No workflow/test/Linux source is changed while this interface is unresolved. Preferred continuation: authorize the original gate owner to expose a bounded redacted partial-receipt export and integrity check, separately from full qualification, preserving actual suite failure and nonqualification. Alternative: an explicit reviewed CI-only raw-record retention policy, with its privacy and access limits. Both require a lead scope/contract decision; this author does not choose one or create helper tasks.
