Read the assistant usage and model that native Pi puts on its `message_end` and `turn_end` records, as `agent_end` already does, so a run interrupted before `agent_end` still reports its latest usage even when the stored event is truncated. Each counter a report supplies replaces its earlier value instead of being added, so repeated reports never double count, and counters it omits keep their earlier values; a missing or invalid count stays unknown rather than zero, and an explicit zero stays zero. Non-assistant messages are ignored, and a record with no assistant message still uses its top-level fields as before. Nothing outside tests registers a usage observer, so stored run tokens are unchanged and the daemon continues to use file storage.
